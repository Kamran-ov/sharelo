# Plan 012 — Web: add an expense in two taps, expense list, edit and delete

Ticket: `tickets/012-web-add-expense.md` · risk: normal

## Current state
Not already done. `frontend/src/App.tsx` routes `/g/:id/expenses` to `Placeholder` (`frontend/src/components/Placeholder.tsx`); `Settings.tsx` has share link, members and the Home toggle only. `GroupShell.tsx` passes `GroupDetail` through `<Outlet context>` (`my_member_id`, `members`, `currency`). There is no `Sheet` component despite 011's layout note: the New-group sheet in `Groups.tsx` is inline.
Backend (010, `docs/api.md`) already has everything the screen writes: `POST/GET groups/{id}/expenses/` (presets `half|personal|full_for_other|percentage{percent_payer}|equal|exact|shares`, advanced `payers+splits+split_type`, foreign `original_currency`+`original_amount_cents` with optional manual `rate_used`), `PATCH/DELETE .../expenses/{eid}/`, `GET categories/`, `GET/PUT category-defaults/`. `ExpenseOutSerializer` carries `payers[{member, paid_cents}]` and `splits[{member, owed_cents}]`, so "you owe/lent" is computed client-side as `owed − paid` for `my_member_id` (ticket Notes; display only, no stored balance).
Gaps found while mapping each screen element to a response field:
- No way to preview a foreign conversion or learn that a rate is missing before Save: `rates.rate()` raises `LedgerError(no_rate)` only inside POST. → one additive read endpoint (below).
- `GET expenses/` has no month totals; ticket asks for a month total on the list. → computed in the client from loaded rows is wrong across pages (a month split over the page boundary). The page response therefore gets an additive `month_totals` (Open questions).
- Description suggestions and "most-used first" categories need no endpoint: both derive from the first page of the list (newest 50), the 20 distinct latest descriptions and category counts over those 50.

## Proposal
**Declared API changes (additive, read-only; nothing existing changes).**
1. `GET groups/{id}/rate/?currency=USD&date=YYYY-MM-DD` → `{currency, date, rate}` (`rate` = group units per 1 foreign unit, string, from `rates.rate`) or 400 `{code:"no_rate"}`; same-currency → 400 `invalid_request`. A `GroupScopedView` (membership check as everywhere). The client converts for display through the same number the POST will store; the POST remains the authority (`rate_mismatch` still guards).
2. `GET expenses/` page object gains `month_totals: {"YYYY-MM": cents}` for the months present in the returned page, summed over the whole filtered set , so a month straddling pages shows the same total on both. The arithmetic lives in `ledger/services/expenses.py: month_totals(group, filters, months) -> dict[str, int]` (one aggregate query on the date's year-month; the view only calls it, hard rule 8). Total = sum of `amount_cents` of non-deleted expenses in that month **including `personal` rows** (what the group's books hold, not "my" share) — assumed, recorded in Open questions.
`make schema` regenerates `schema.json` and `types.ts`; `docs/api.md` rows added.

**Frontend** (stack from 011; no business logic in TS beyond display arithmetic and input parsing).
- `src/money.ts`: `parseAmount(text) → cents | null`: accepts `12`, `12.5`, `12,50`, `12.50`, rejects more than two decimals, empty, negatives, `1,234.50`-style separators, zero; integer maths on the digit string (no float, no `Number("12.5")*100`). `formatCents(cents)` for **display only**: locale pinned to `en`, exactly two fraction digits, no currency symbol, no grouping (`4210 → "42.10"`), built from integer division/modulo of the cents (no `/100` float); the currency code is rendered as separate text. The literal "42.10" in the KEY assertion therefore does not depend on the browser locale.
- `src/presets.ts`: `toApiPreset(who: "half"|"personal"|"all_other"|"custom", paidBy: "me"|"other", customPercent, ids) → {preset, params}` — the exhaustive 4 × 2 mapping the ticket asks for. `half→half`, `personal→personal`, `all_other→full_for_other {other_id}` (the one who is not the payer), `custom→percentage {percent_payer}`. Who-paid flips the payer, and with it `other_id` and the meaning of the slider (it is always the *payer's* percent).
- `src/pages/Expenses.tsx`: list via `useInfiniteQuery` (page 1.., "Load more" button; 404 past the end is never requested because the button hides when `results` of loaded pages ≥ `count`). Month headers group on the first seven characters of the row's `date` string (`"2026-10"`), never `new Date(date)`, and show `month_totals[that key]`. Row per ticket; wording: `owed−paid` for me → `>0` "you owe 12.50", `<0` "you lent 12.50", `0` with split_type `personal` "personal", `0` otherwise "settled". Foreign rows show original amount + currency in small text. Floating "+" (≥ 56 px) opens the add sheet; row tap opens the edit sheet.
- `src/components/Sheet.tsx`: full-height bottom sheet (`role="dialog"`, focus on open, Esc and backdrop close, `max-h-dvh` + inner scroll so the keyboard never forces horizontal scroll). `Groups.tsx` New-group is left as is (out of scope to refactor).
- `src/components/CategoryPicker.tsx` (opened by the chip, inside the sheet): data = `GET categories/` (two-level tree, children ordered by id = seed order) plus use counts per category id over the first list page (50 newest). Parents are tabs, ordered by the summed use of their children then seed order; children are a grid ordered by own use count descending, ties and unused by seed order. The tab of the current category is open first. Choosing a child sets the category and re-runs the default-split preselection.
- Description suggestions: `descriptionSuggestions(rows)` returns the 20 most recent distinct descriptions (case-insensitive) each with the category of the expense it came from. Tapping one sets description **and** category, and the category change re-runs the default-split preselection (same code path as the picker).
- `src/pages/ExpenseSheet.tsx`: one form for add and edit. Field order as in the ticket: amount (`inputmode="decimal"`, autofocus), description with suggestion chips, category chip (default: the category of the newest expense on the first list page; in a group with none, **Uncategorized › General**, looked up by name in `GET categories/` because it is the one seeded leaf with no domain meaning, so a fresh group's chip never lands on, say, Games), date (default = the browser's local calendar date built from `getFullYear/getMonth/getDate` and zero-padded to `YYYY-MM-DD`, never `toISOString().slice(0,10)`, which is yesterday after local midnight in Rome; tap opens the native date input), Who paid (segmented for 2 members, `<select>` for more), Who it's for (segmented for 2 members). Group with ≠ 2 members: the "half/all other/custom" row is replaced by "Equal among everyone" (preset `equal`; `half` is only the two-member name of it) and "Only me", and Advanced is the way to subsets — see Open questions. Category change preselects the category default (`category-defaults/` fetched once per group): `equal`/`half`→50/50, `personal`, `full_for_other`, `percentage` → Custom with its percent; any other stored preset (`exact`, `shares`) falls back to 50/50 in the sheet and is not offered as default. No default → `half` (the "equal" fallback of the KEY test).
- Advanced (collapsed `<details>`): per-member exact amounts (must sum to total, shown remaining), shares (integers), equal among a chosen subset (checkboxes; sent as preset `shares` with 1 for each chosen member, so flooring and leftover cents stay in `splits.py`). Foreign currency: amount + currency `<select>` (EUR first, same fixed list as 011); on change/date change calls the rate endpoint; shows `≈ <converted> EUR` computed client-side for display only and never written into the body (the row after Save shows the server's `amount_cents`); `no_rate` shows an alert and a manual-rate field, Save disabled until a valid rate is typed; the POST sends `original_currency`, `original_amount_cents` and (manual only) `rate_used`, never `amount_cents`.
- Save: `POST`; `onMutate` inserts an optimistic row (negative temp id, amounts from the form, marked `pending`) into the first cached page and closes the sheet; pending rows are rendered non-interactive (not a button, `aria-busy`) until replaced, so the edit sheet can never open on a temp id. On error: roll back, reopen the sheet with the form values and show the API `detail`. On success: replace the temp row with the server row, invalidate balances, and only then show the toast "Saved" with Undo; the 5 s window starts at `onSuccess` and Undo sends `DELETE` to the **server id**, then invalidates expenses and balances. Toast is a small `role="status"` component (`src/components/Toast.tsx`), timer cleared on unmount.
- Edit: same form prefilled from the row (a row with `payers.length > 1` opens read-only with the text "multiple payers — edit not supported yet", no Save, Delete kept, so an edit can never collapse payers to one; otherwise payer = the single payer. If payers/splits do not reproduce any of the four presets, the "Who it's for" row shows "Custom split — edit in Advanced" and Advanced opens prefilled with exact amounts, because the API refuses to guess). Save → `PATCH` with preset+params (always sent with amount/payer changes). Delete → confirm dialog → `DELETE`.
- Settings tab: "Default split per category" list (parents → children). Row shape is the API's (`docs/api.md`): `GET/PUT category-defaults/` map `"<category id>" → {preset, params}`; `half` is stored and returned as `equal`; PUT replaces the whole set, so the client sends the loaded map with the one change. Each row is a select: *No default* (row omitted from the PUT; the sheet falls back to 50/50), *50/50* (`equal`), *Only me* (`personal`), *All the other* (`full_for_other`, stored **without** `other_id`; resolved against the payer's counterpart at form time, which is why it is only offered for the 2-member case in the sheet and ignored, falling back to equal, in other groups), *Custom %* (`percentage` with `basis_points`-free `percent_payer`, 5 % steps, an inline number input next to the select, same semantics as the slider: the payer's percent). Saved on change with a small "Saved" mark. Unmapped stored presets (`exact`, `shares`, written by other clients) display as "Other (kept)" and are preserved untouched in the PUT.
- Layout rules from 011 stay: no `overflow-x: hidden` anywhere; wrap/truncate on elements.

## Open questions
- Assumed: `month_totals` is an additive API field (the ticket cannot show a correct month total across pages otherwise).
- Assumed: groups with ≠ 2 members get "Equal among everyone / Only me" in the main row and subsets via Advanced (ticket specifies the segmented control only for the 2-member case).
- Assumed: "equal among a chosen subset" is sent as `shares` (1 each) so rounding stays in `splits.py`.
- Assumed: the e2e fixture gains one USD rate; GBP deliberately has none.
- Assumed: the month total includes `personal` rows.
- Assumed: a fresh group's category chip is Uncategorized › General.
- Assumed: multi-payer rows are read-only in the edit sheet (Delete only) until a later ticket.
- Assumed: Settings offers *No default*, 50/50, Only me, All the other, Custom % (with a percent input); `exact`/`shares` defaults written elsewhere are shown as "Other (kept)" and preserved.

## Field table (screen element → response field)
| Element | Source |
|---|---|
| row description, date, amount | `expenses[].description`, `date`, `amount_cents` (+ `currency`) |
| foreign small text | `original_amount_cents`, `original_currency` |
| sub-category name | `expenses[].category` id joined to `GET categories/` children `name` |
| "you paid" / "<name> paid" | `payers[].member` vs `GroupDetail.my_member_id`; name from `GroupDetail.members[].display_name` |
| "you owe / lent / personal / settled" | `splits[].owed_cents − payers[].paid_cents` for `my_member_id`; `split_type == "personal"` for the zero case |
| month total | `month_totals["YYYY-MM"]` |
| paging | `count`, `page`, `results` |
| rate preview | `GET rate/` → `rate` (string) or `code: no_rate` |
| category defaults | `GET category-defaults/` → `{id: {preset, params}}` |

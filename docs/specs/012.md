# Plan 012 — Web: add an expense in two taps, expense list, edit and delete

Ticket: `tickets/012-web-add-expense.md` · risk: normal

## Current state
Not already done. `frontend/src/App.tsx` routes `/g/:id/expenses` to `Placeholder` (`frontend/src/components/Placeholder.tsx`); `Settings.tsx` has share link, members and the Home toggle only. `GroupShell.tsx` passes `GroupDetail` through `<Outlet context>` (`my_member_id`, `members`, `currency`). There is no `Sheet` component despite 011's layout note: the New-group sheet in `Groups.tsx` is inline.
Backend (010, `docs/api.md`) already has everything the screen writes: `POST/GET groups/{id}/expenses/` (presets `half|personal|full_for_other|percentage{percent_payer}|equal|exact|shares`, advanced `payers+splits+split_type`, foreign `original_currency`+`original_amount_cents` with optional manual `rate_used`), `PATCH/DELETE .../expenses/{eid}/`, `GET categories/`, `GET/PUT category-defaults/`. `ExpenseOutSerializer` carries `payers[{member, paid_cents}]` and `splits[{member, owed_cents}]`, so "you owe/lent" is computed client-side as `owed − paid` for `my_member_id` (ticket Notes; display only, no stored balance).
Gaps found while mapping each screen element to a response field:
- No way to preview a foreign conversion or learn that a rate is missing before Save: `rates.rate()` raises `LedgerError(no_rate)` only inside POST. → one additive read endpoint (below).
- `GET expenses/` has no month totals; ticket asks for a month total on the list. → computed in the client from loaded rows is wrong across pages (a month split over the page boundary). The page response therefore gets an additive `month_totals` (Open questions).
- Description suggestions and "most-used first" categories need no endpoint: both derive from the first page of the list (newest 50), the 20 distinct latest descriptions and category counts over those 50.

## Proposal
**Declared API changes (additive, read-only; nothing existing changes).**
1. `GET groups/{id}/rate/?currency=USD&date=YYYY-MM-DD` → `{currency, date, rate}` (`rate` = group units per 1 foreign unit, string, from `rates.rate`) or 400 `{code:"no_rate"}`; same-currency → 400 `invalid_request`. A `GroupScopedView` (membership check as everywhere). The client converts for display through the same number the POST will store; the POST remains the authority (`rate_mismatch` still guards).
2. `GET expenses/` page object gains `month_totals: {"YYYY-MM": cents}` for the months present in the returned page, summed over the whole filtered set (one aggregate query on `date__year/month`), so a month straddling pages shows the same total on both. Total = sum of `amount_cents` of non-deleted expenses in that month (what the group spent, not "my" share).
`make schema` regenerates `schema.json` and `types.ts`; `docs/api.md` rows added.

**Frontend** (stack from 011; no business logic in TS beyond display arithmetic and input parsing).
- `src/money.ts`: `parseAmount(text) → cents | null`: accepts `12`, `12.5`, `12,50`, `12.50`, rejects more than two decimals, empty, negatives, `1,234.50`-style separators, zero; integer maths on the digit string (no float, no `Number("12.5")*100`). `formatCents(cents, currency)` via `Intl.NumberFormat` on `cents/100` for **display only**.
- `src/presets.ts`: `toApiPreset(who: "half"|"personal"|"all_other"|"custom", paidBy: "me"|"other", customPercent, ids) → {preset, params}` — the exhaustive 4 × 2 mapping the ticket asks for. `half→half`, `personal→personal`, `all_other→full_for_other {other_id}` (the one who is not the payer), `custom→percentage {percent_payer}`. Who-paid flips the payer, and with it `other_id` and the meaning of the slider (it is always the *payer's* percent).
- `src/pages/Expenses.tsx`: list via `useInfiniteQuery` (page 1.., "Load more" button; 404 past the end is never requested because the button hides when `results` of loaded pages ≥ `count`). Month headers with `month_totals`. Row per ticket; wording: `owed−paid` for me → `>0` "you owe 12.50", `<0` "you lent 12.50", `0` with split_type `personal` "personal", `0` otherwise "settled". Foreign rows show original amount + currency in small text. Floating "+" (≥ 56 px) opens the add sheet; row tap opens the edit sheet.
- `src/components/Sheet.tsx`: full-height bottom sheet (`role="dialog"`, focus on open, Esc and backdrop close, `max-h-dvh` + inner scroll so the keyboard never forces horizontal scroll). `Groups.tsx` New-group is left as is (out of scope to refactor).
- `src/pages/ExpenseSheet.tsx`: one form for add and edit. Field order as in the ticket: amount (`inputmode="decimal"`, autofocus), description with suggestion chips, category chip (default: last-used category of this group from the first list page, else first child), date (today; tap opens the native date input), Who paid (segmented for 2 members, `<select>` for more), Who it's for (segmented for 2 members). Group with ≠ 2 members: the "half/all other/custom" row is replaced by "equal among everyone" and "Only me", and Advanced is the way to subsets — see Open questions. Category change preselects the category default (`category-defaults/` fetched once per group): `equal`/`half`→50/50, `personal`, `full_for_other`, `percentage` → Custom with its percent; any other stored preset (`exact`, `shares`) falls back to 50/50 in the sheet and is not offered as default. No default → `half` (the "equal" fallback of the KEY test).
- Advanced (collapsed `<details>`): per-member exact amounts (must sum to total, shown remaining), shares (integers), equal among a chosen subset (checkboxes; sent as preset `shares` with 1 for each chosen member, so flooring and leftover cents stay in `splits.py`). Foreign currency: amount + currency `<select>` (EUR first, same fixed list as 011); on change/date change calls the rate endpoint; shows `≈ <converted> EUR`; `no_rate` shows an alert and a manual-rate field, Save disabled until a valid rate is typed; the POST sends `original_currency`, `original_amount_cents` and (manual only) `rate_used`, never `amount_cents`.
- Save: `POST`; `onMutate` inserts an optimistic row (negative temp id, amounts from the form) into the first cached page; on error rolls back and keeps the sheet open with the API `detail`; on success invalidates expenses, balances. Sheet closes; toast "Saved" with Undo for 5 s → `DELETE`, then invalidate. Toast is a small `role="status"` component (`src/components/Toast.tsx`), timer cleared on unmount.
- Edit: same form prefilled from the row (payer = the single payer or the one with most; if payers/splits do not reproduce any of the four presets, the "Who it's for" row shows "Custom split — edit in Advanced" and Advanced opens prefilled with exact amounts, because the API refuses to guess). Save → `PATCH` with preset+params (always sent with amount/payer changes). Delete → confirm dialog → `DELETE`.
- Settings tab: "Default split per category" list (parents → children, each a select of the four presets; `PUT category-defaults/` replaces the whole set, so the client sends the full map from the loaded one with the one change). Saved on change with a small "Saved" mark.
- Layout rules from 011 stay: no `overflow-x: hidden` anywhere; wrap/truncate on elements.

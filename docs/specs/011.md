Ticket: `tickets/011-web-shell-signin-groups.md` · risk: normal

## Current state

## Proposal
**Frontend stack** (fixed for 012–015): React Router v6, TanStack Query v5, Tailwind CSS v4 (`@tailwindcss/vite`, no config file), `openapi-typescript` generating `src/api/types.ts` from `schema.json` (npm script `types`; the generated file is committed and `make lint` runs `tsc` over it). No component library. Layout: `src/api.ts` (fetch wrapper), `src/auth.tsx` (`useMe`), `src/pages/{Login,Groups,Join,GroupShell,Settings}.tsx`, `src/components/{Sheet,GoogleButton,Placeholder}.tsx`. A page holds no business logic; it calls endpoints and renders. Strings in English.

**`api.ts`**: `api<T>(method, path, body?)` — `credentials: "same-origin"`, JSON in/out, for non-GET reads the `csrftoken` cookie and sends `X-CSRFToken`; if the cookie is missing it first does `GET /api/me` (which sets it) and retries reading once. A non-2xx response becomes `ApiError{status, code, detail}`; a non-JSON error body becomes `code: "network"`. A 401 never redirects from inside `api.ts`; the route guard decides.

**Routing and guard**: `/login`, `/groups`, `/join/:token`, `/g/:id/{expenses,balances,recurring,settings}` (default `expenses`). `RequireAccess` wraps `/groups` and `/g/*`: loads `/api/me`; `authenticated` or non-empty `guest_memberships` passes, otherwise `<Navigate to="/login">`. `/login` and `/join/*` are public; an authenticated user visiting `/login` goes to `/groups`. A guest with memberships opening `/groups` sees only their groups (the API already returns exactly the union; the page does not filter). Group-scoped 404 (non-member) renders "Group not found" with a link back, no redirect loop.

**Pages**
- Login: email + password, "Create account" toggle (adds display name, calls register), submit errors inline from `detail` (no redirect). "Sign in with Google" button rendered only when `me.google_enabled`; loads the GIS script on demand, calls `auth/google` with the ID token.
- Groups: list (name, currency, "main" badge, "linked to Home" for active-linked non-main groups); "New group" opens a bottom sheet: name, currency select (EUR first, then a fixed list of common ISO codes), "make this my main group" checkbox, default checked iff the profile has no main group and disabled otherwise (the API refuses a second main with `main_group_exists`; the UI does not offer it).
- Join: public preview (group name, currency, member names). Signed-in: one "Join" button. Guest: name field + "Join". `name_taken` shown inline. On success navigate to `/g/:id/expenses`.
- Group shell: header with group name, `<Outlet/>`, bottom nav of four 44 px+ tabs. Expenses/Balances/Recurring render a placeholder "coming in ticket 012/013/014". Settings: share link (`${origin}/join/${share_token}`) with a Copy button (`navigator.clipboard`, with a visible "Copied" state, asserted in e2e under the granted clipboard permissions), the members list (so a guest sees her own name), and, for signed-in non-main members, the "Linked to Home" toggle posting `groups/{id}/link`.
- Layout: a single centred column `max-w-[480px]`, `min-h-dvh`, with **no** `overflow-x: hidden` (or `overflow: hidden`) on `html`, `body`, the column or any wrapper, so `documentElement.scrollWidth` measures real content. Long text uses `break-words`/`truncate` at the element, not a clip on an ancestor.

**Fields each screen reads** (`docs/api.md`, ledger table and `/api/me`):
| Screen element | Field |
|---|---|
| "main" badge on `/groups` | `GET groups/` → `is_main` |
| name, currency on `/groups` | `GET groups/` → `name`, `currency` |
| "linked to Home" badge on `/groups` | **missing today**: `GroupSummarySerializer` (`ledger/api/serializers.py:150`) has no `link_active`; only the detail has it. See plan change below |
| join preview | `GET join/{token}/` → `group_name`, `currency`, `member_names` |
| join result | `POST join/{token}/` → `group_id`, `member_id` |
| share link | `GET groups/{id}/` → `share_token` |
| members list in Settings (guest sees her name) | `GET groups/{id}/` → `members[].display_name`, `is_guest`, and `my_member_id` to mark "you" |
| link toggle state | `GET groups/{id}/` → `link_active` (`null` for main group and guests: toggle hidden); write `POST groups/{id}/link {active}` |
| main-checkbox default | `/api/me` → `profile.main_group_id` |
| guard | `/api/me` → `authenticated`, `guest_memberships` |

**Declared plan change to the API (additive, read-only):** `GET groups/` rows gain `link_active: bool | null` (same meaning and same source, the profile's `GroupLink.active`, as in the detail; `null` for the main group and for guest sessions). `_group_summary` in `ledger/api/views.py` computes it from one extra `GroupLink` query for the whole list (not per row). `GroupSummarySerializer` gains the field; `make schema` regenerates `schema.json` and `types.ts`; `docs/api.md` row updated. Tests: `test_group_list_carries_link_active_per_group` (main → `null`, active trip → `true`, unlinked trip → `false`, guest session → `null`; twin of the detail test) and `test_group_list_query_count_is_constant_with_link_field` (3 vs 10 groups). The existing 010 schema-equality test stays the staleness guard. Nothing else in the API changes.

**Backend support for e2e (backend changes: this section, plus the additive `link_active` above)**
- Dedicated database: the e2e Django, `e2e_reset`, `migrate` and the CI job all use a `DATABASE_URL` whose database name ends in `_e2e` (laptop/cloud default `postgres://sharelo:sharelo@localhost:5432/sharelo_e2e`; the Makefile's `e2e` target exports it, overriding the dev default). `globalSetup` runs `python manage.py e2e_prepare`, which (E2E-guarded as below) creates the database if absent via a connection to the `postgres` maintenance database, then calls `migrate`. `scripts/cloud-setup.sh` is not changed. The CI service container only has `sharelo`, so `e2e_prepare` creates `sharelo_e2e` there too. `migrate` therefore always runs before the first reset, on an empty database.
- `settings.py`, `E2E = os.environ.get("E2E") == "1"`. In the E2E branch: `DEBUG = False` (the e2e server runs as production does; nothing depends on DEBUG), `ALLOWED_HOSTS = ["localhost", "127.0.0.1"]` set outright, `SESSION_COOKIE_SECURE = CSRF_COOKIE_SECURE = False` (plain http), auth throttle rate lifted. Guard: if `E2E` and an `ALLOWED_HOSTS` env override is present and contains anything but those two hosts → `ImproperlyConfigured`; if `E2E` and the database name does not end in `_e2e` → `ImproperlyConfigured` at boot, so a laptop dev database can never be served in E2E mode either.
- Required env, supplied by the Makefile target and by the CI job explicitly (CI has no `.env`): `E2E=1`, `DATABASE_URL=…/sharelo_e2e`, `SECRET_KEY` (a test value, as the Makefile's). The Playwright `webServer.env` passes the same.
- Single-origin: the browser Origin `http://localhost:4173` must equal the Host Django sees through the proxy, so Playwright's `baseURL` is `http://localhost:4173`, never `127.0.0.1`.
- `ledger/management/commands/e2e_reset.py` raises `CommandError` unless **both** `E2E=1` and the connection's `NAME` ends in `_e2e`. It wipes in one transaction, with `TRUNCATE … RESTART IDENTITY CASCADE`: every `ledger` table that holds user data (`Group`, `Member`, `Expense`, `ExpensePayer`, `ExpenseSplit`, `Settlement`, `RecurringRule`, `CategoryDefault`, `GroupLink`, …), `accounts.Profile`, `auth.User` and `django_session`. It never touches `Category` (seeded by migration), `ExchangeRate`, `django_migrations`, content types or permissions. It then seeds: profile `a@example.com` / `password1234` ("Alice") with Home (EUR, main), partner profile B (`b@example.com`) as a second member of Home, and one trip "Rome trip" created by B with the fixed `share_token` `e2e-rome-token` and member B only (A is not in it). Seeding uses `groups.create_group`/`join_group_by_token`, so the fixture obeys the invariants. Truncating `auth.User` and sessions is what lets `test_register_new_account_lands_on_groups` pass on a second run.
- Backend tests (`tests/test_e2e_commands.py`, Postgres): `test_e2e_reset_refuses_without_e2e_flag`, `test_e2e_reset_refuses_when_database_name_does_not_end_in_e2e` (the KEY pair for the wipe: refusals leave a pre-created user row intact), `test_e2e_reset_wipes_and_seeds_fixture_on_e2e_database` (legitimate success on a `_e2e` name, counts: 2 profiles, 2 groups, Home main for A; categories and rates untouched), `test_e2e_reset_twice_gives_same_fixture`, `test_e2e_settings_refuse_foreign_allowed_hosts`. The command reads the name from one small function `database_name()`; tests patch that function to return a `_e2e` name while running against the normal test database, so the wipe is exercised without a second database.
- Playwright `globalSetup` runs `e2e_prepare` once; a `beforeEach` fixture runs `e2e_reset` (commands that finish; no server is started by hand).

**Playwright**: `frontend/e2e/*.spec.ts`, `frontend/playwright.config.ts`: `webServer` array — Django (`E2E=1 python manage.py runserver 8001 --noreload`) and `vite preview --port 4173` on the built bundle; `reuseExistingServer: false`; Playwright owns start and stop. `vite.config.ts` gains `preview.proxy` for `/api` → `127.0.0.1:8001` with `changeOrigin: false` (Host `localhost:4173` equals the browser Origin, same CSRF reasoning as dev). Project device: viewport 390×844 touch, Chromium, `baseURL: http://localhost:4173`, context permissions `clipboard-read`/`clipboard-write`. Browser resolution: the config sets no `executablePath`. In the cloud session `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers` already holds Chromium and nobody runs `playwright install`; on a GitHub runner neither exists, so the workflow (not `make e2e`) runs `npx playwright install --with-deps chromium` first. If the project's pinned `@playwright/test` expects a different Chromium revision than the cloud image has, the config falls back to `executablePath: '/opt/pw-browsers/chromium'` when that path exists. One worker, since tests share one database. A helper `shot(page, testInfo)` saves `docs/screenshots/011/<test-name>.png`. `make e2e` = `cd frontend && npm run build && npx playwright test`. CI job `e2e`: Postgres service, Python + Node setup, `make install`, `npx playwright install --with-deps chromium` (workflow-only step), `make e2e` with `E2E=1`, `SECRET_KEY`, `DATABASE_URL` (`…/sharelo_e2e`) as explicit job env; the Playwright report/PNGs are uploaded as an artifact.

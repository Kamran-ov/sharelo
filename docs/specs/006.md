# Plan 006 — Profiles, main group, linked sub-groups, Move to Home

Ticket: `tickets/006-profiles-and-linking.md` · risk: risky (identity, money, migration)

## Current state
- `backend/accounts/models.py` holds a stub `Profile(email)`; migration `accounts/0001_initial.py`. Nothing creates Profiles yet
  (no code path, no fixture), so the table is empty everywhere. `GroupLink` does not exist. Not already done.
- `ledger.Member.profile` is a nullable FK to `accounts.Profile`; the only Member constraint is `uniq_member_group_display_name`.
  A profile can therefore appear twice in one group today. `Group.share_token` is unique.
- `Settlement` has `twin` (nullable self-FK, `SET_NULL`), `amount_cents > 0` and `from != to` CHECKs; `balances.record_settlement`
  creates a single settlement and validates membership. `net_balances` / `simplify_debts` give a group's debts.
- `ledger/services/groups.py` does not exist.

## Proposal
**Models**
- `accounts.Profile`: `user` OneToOne(`settings.AUTH_USER_MODEL`, CASCADE), `display_name`, `main_group` FK(`ledger.Group`, null, `SET_NULL`,
  `related_name="+"`), `created_at`. The stub `email` is dropped (identity email lives on `User`). New migration `accounts/0002`
  (never edit 0001): `RunPython` deletes stub rows first so the non-null `user` column can be added; then drop `email`, add the fields.
- `ledger.GroupLink`: `profile` FK(CASCADE), `sub_group` FK(Group, CASCADE), `main_group` FK(Group, CASCADE), `active` bool default True,
  `created_at`. Unique (`profile`, `sub_group`); CHECK `sub_group != main_group`.
- `Member`: add partial `UniqueConstraint(profile, group)` where `profile IS NOT NULL` — "a profile appears in a group at most once"
  enforced by the database, not only the service. New ledger migration.

**`ledger/services/groups.py`** (all writes `transaction.atomic`, `LedgerError` only)
- `create_group(profile, name, currency, as_main=False) -> Group`: creates Group + Member(display_name=profile.display_name, profile).
  `as_main=True` and no main group yet → sets `profile.main_group`. `as_main=True` with a main group already set →
  `LedgerError("main_group_exists")`. `as_main=False` and a main group exists → active `GroupLink(sub=new, main=profile.main_group)`.
  No main group and `as_main=False` → no link, no main group set.
- `join_group_by_token(token, display_name, profile=None) -> Member`: unknown token → `LedgerError("unknown_group")`. With a profile:
  an existing Member of that profile in the group is returned unchanged (idempotent; display_name ignored); otherwise creates one named
  `display_name` and applies the same auto-link rule (a link already present is left as is, including inactive). Joining the
  profile's own main group never creates a link to itself. Guest (no profile): creates Member with `profile=None`, no link. A name
  already taken in the group → `LedgerError("name_taken")` (checked in the service, DB constraint is the backstop).
- `set_link_active(profile, group, active) -> GroupLink`: updates the existing link; no link → `LedgerError("no_link")`.
  Never creates a row, so toggling cannot duplicate.
- `move_debt_to_home(trip_group, from_profile, to_profile, amount_cents, date) -> tuple[Settlement, Settlement]`: one `atomic` block.
  Refusals (each `LedgerError`): `amount_not_positive`; `same_profile`; `no_main_group` (either profile); `main_group_mismatch`
  (different main groups); `trip_is_main_group`; `not_a_member` (profile has no Member in the trip or in the main group);
  `exceeds_debt` — amount > cents `from` owes `to` in `simplify_debts(net_balances(trip))`. The debt is read from the trip's simplified
  transfers, so with 3+ people only a direct from→to transfer counts (conservative; assumed, see open questions).
  Then creates S1 in the trip (from_member→to_member) and S2 in the main group (to_member→from_member), same amount and date,
  currency = each group's own currency (amount is in the trip currency; if currencies differ → `LedgerError("currency_mismatch")`,
  no conversion in this ticket), sets `S1.twin=S2`, `S2.twin=S1`. Effect: trip nets move toward zero by the amount;
  main-group nets move by the same amount the other way (`from` now owes `to` at Home).
  Rows are created via `Settlement.objects.create` directly (not `record_settlement`) so that the pair is a single write unit.

## Edge cases
- Moving the whole debt then moving again → second call `exceeds_debt` (debt now 0).
- Three people, A owes C 2000 and B owes C 1000: A→B move is refused (no direct simplified transfer), A→C 2000 passes.
- Trip debt is in a different direction than requested, or none at all → `exceeds_debt`.
- Both profiles have a Member in the trip but one was added after the debt: debt is computed from current nets only.
- Concurrent double-click: two calls each read the debt then insert → could overdraw. Mitigation: `select_for_update` on the trip `Group` row
  inside the atomic block before reading nets.

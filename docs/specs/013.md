# Plan 013 — Web: balances, settle up, Move to Home

Ticket: `tickets/013-web-balances-settle.md` · risk: normal

## Current state
Not done. `frontend/src/App.tsx` routes `/g/:id/balances` to `Placeholder`. `GroupShell.tsx` hands `GroupDetail` (`my_member_id`, `members`, `currency`) through `<Outlet context>`; 012 added `Sheet.tsx`, `Toast.tsx`, `lib/{money,dates}.ts` (`parseAmount`, `formatCents`, local-date helper) and the invalidate-on-mutate pattern in `ExpenseSheet.tsx`, all reused here.
Backend (`backend/ledger/api/views.py`, `docs/api.md`):
- `GET groups/{id}/balances/` returns `currency`, `nets`, `transfers[{from_member,to_member,amount_cents}]`, `members[{member_id,paid,owed_share,net}]`. No `can_move_to_home`.
- `GET/POST groups/{id}/settlements/` exist (`SettlementOutSerializer`: `id, from_member, to_member, amount_cents, currency, date, notes, twin`). **No DELETE**. `Settlement` has no `deleted_at` (`ledger/models.py:256`), unlike `Expense`/`RecurringRule`.
- `POST groups/{id}/move-to-home` takes `{to_profile, amount_cents, date}` and refuses via `services/groups.py:move_debt_to_home` (`trip_is_main_group`, `no_main_group`, `main_group_mismatch`, `exceeds_debt`, `currency_mismatch`). The client has no profile ids today: `GroupDetail.members` carries no `profile`.
- The History badge needs the twin's group name; `twin` is only an id.

## Proposal
**Declared API changes (additive unless stated).**
1. `balances.transfers[]` gains `can_move_to_home: bool` and `to_profile: int | null` (the creditor's profile id, null for a guest). Rule in `services/groups.py: can_move_to_home(group, viewer_profile, from_member, to_member)` (rule 8, view only calls it): true iff the viewer is the debtor's profile (`from_member.profile == viewer`), the creditor has a profile, the group is not the viewer's main group, both profiles have a `main_group` and it is the same one, and `group.currency == home.currency`. It is a hint for showing the button; `move_debt_to_home` stays the authority. Debtor-only is assumed, because the endpoint's `from_profile` is the caller (Open questions). An anonymous guest session viewing balances gets `false` everywhere.
2. `DELETE groups/{id}/settlements/{sid}/` (same `GroupScopedView` membership check): `services.balances.delete_settlement(group, sid)`. Refuses a row with a `twin` → 400 `twin_settlement` (the pair is undone only together, out of scope here); wrong group or already deleted → 404 `not_found`. Soft delete (CLAUDE.md FACTS): new migration `0007_settlement_deleted_at` adds `deleted_at` (null), `ActiveSettlementManager` as `objects`, `all_objects` plain, `base_manager_name = "all_objects"` exactly as `Expense`. The balance query in `balances._settlement_flows` uses `objects`, so a deleted row drops out of every net with no further change; `twin` FK resolves through the base manager. The new migration is additive; no committed migration is edited.
3. `SettlementOutSerializer` gains `twin_group_name: str | null` (name of `twin.group`) and `is_home_side: bool` (true iff `twin` is set and this row's group is the `main_group` of the profile of either of its members; computed from prefetched member profiles, constant queries). Badge rule, one for both sides: for a row with a `twin`, the trip name is `twin_group_name` when `is_home_side`, else this group's own name; the badge reads "<trip name>: moved to Home" (the PLAN.md sentence "Rome trip: €200 moved to Home", amount shown in the row). So Rome's History and Home's History both say "Rome trip: moved to Home".
`make schema` regenerates `schema.json`/`types.ts`; `docs/api.md` rows added.

**Frontend** (display arithmetic and input parsing only).
- `src/lib/balanceText.ts`: `topCardText(net, currency)` → `{tone: "owed"|"owe"|"settled", text}`: `net>0` "you are owed 84.20", `<0` "you owe 12.00" (absolute value via integer ops through `formatCents`), `0` "all settled". `net` = `members[my_member_id].net` from the response; never recomputed.
- `src/pages/Balances.tsx` (`/g/:id/balances`): top card; per-member rows (`display_name`, net with sign colour + text, not colour alone); "Suggested payments" list from `transfers` ("B pays A 21.05", names from `GroupDetail.members`, "you" for me) each with **Settle** and, when `can_move_to_home`, **Move to Home**; collapsed `<details>` "History" from `GET settlements/` (date, "A → B", amount, note, badge "Moved to <twin_group_name>" when `twin` set). One `useQuery` per endpoint; mutations invalidate `balances` and `settlements`; no client cache beyond TanStack's refetch.
- `src/pages/SettleSheet.tsx` (uses `Sheet`): from/to (`<select>` of members, prefilled from the transfer), amount text input prefilled with `formatCents(transfer.amount_cents)`, date (local calendar date helper from 012), note. Amount rule, exact: the sheet uses a new `parseAmountForSubmit(text)` in `lib/money.ts` that reuses `parseAmount`'s grammar but accepts zero (`0`, `0.00`, `0,0` → 0); it returns null only for text that is not an amount ("abc", "", "12.345", negatives). Save is enabled iff it is non-null, so zero is sent as `amount_cents: 0` and the server's `amount_not_positive` `detail` is rendered inline verbatim. `parseAmount` and `ExpenseSheet` are unchanged, so the 012 tests stay green untouched. On success: close, toast "Settled" with Undo (5 s window starts at `onSuccess`, `DELETE settlements/{server id}/`, then invalidate). Same from/to is refused inline by the server (`same_member`).
- `src/pages/MoveToHomeSheet.tsx`: shows "Rome trip: 200.00 moved to Home" on both sides — "In Rome trip: Bea pays Alice 200.00 (settles the debt)" and "In Home: Alice owes Bea 200.00" — amount field prefilled with the full transfer, editable down (no slider). Debt direction is the same on both lines, taken from the transfer's `from_member` (debtor) and `to_member`: "In Rome trip: Bea pays Alice 200.00 — settles the trip" and "In Home: Bea owes Alice 200.00" (the Home twin row runs Alice → Bea, which is what keeps Bea the debtor in Home; the sheet never shows row direction). With 3+ members the prefilled amount is the simplified transfer, which can exceed the direct debt `move_debt_to_home` checks (006 decision: direct transfers only); inline `exceeds_debt` is then the intended outcome. Confirm → `POST move-to-home {to_profile, amount_cents, date}`; `exceeds_debt` rendered inline. After success both queries invalidate; the home group's balances are fetched fresh when opened (separate query key per group id).
- Wiring: `App.tsx` replaces the Balances placeholder. Settings is untouched.
- Layout rules from 011/012 stay: no `overflow-x: hidden`, wrap/truncate on elements, no horizontal scroll at 390 px.

## Open questions

- Assumed: Move to Home is offered to the debtor's own session only (the endpoint's `from_profile` is the caller), so the creditor does not see the button.
- Assumed: a zero amount is sent to the server on purpose so the server's refusal is shown (ticket's KEY twin: "shows the API error inline").
- Assumed: a third member of a 3+ member trip sees another couple's Home name in the badge via `twin_group_name`; acceptable here.
- Assumed: DELETE of a twinned settlement is refused (400 `twin_settlement`); Move-to-Home undo is a later ticket.

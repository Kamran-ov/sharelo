Ticket: `tickets/014-web-recurring.md` · risk: normal

## Current state
Not done. `frontend/src/App.tsx:25` routes `/g/:id/recurring` to `Placeholder`.
Backend already has everything but three things (`backend/ledger/api/`, `docs/api.md`):
- Rules CRUD + `pause|resume|skip` (`views.py` `RuleListView`, `RuleDetailView`, `RuleActionView`), `RuleOutSerializer` (`id … next_date, end_date, paused`), services in `ledger/services/recurring.py` (`next_occurrence`, `first_occurrence`, `skip_next`, `generate_due`).
- **Skip on a paused rule is allowed** (`skip_next` has no check; `test_recurring_create_pause_skip_resume_roundtrip` skips while paused). The ticket's KEY pair needs an API error for this case.

- `e2e_reset` (`management/commands/e2e_reset.py`) has no options. Frontend reuses 012's `Sheet`, `Toast`, `lib/{money,dates,presets,expenseBody}.ts`, `ExpenseSheet` form pieces, and the invalidate-on-mutate pattern.

## Proposal
**Backend (additive, one behaviour change).**
1. `services/recurring.skip_next` raises `LedgerError("rule_paused")` for a paused rule (rule 8: the check lives in the service; API maps it to 400 with `detail` like other LedgerErrors). Rationale: a paused rule creates nothing, so "skip the next occurrence" has no meaning and would silently move the cursor.
2. `ExpenseOutSerializer` gains `recurring_rule: int | null` (existing FK `Expense.recurring_rule`). `select_related` not needed (id column only).
3. New model `JobRun(name unique, last_run_at)` — migration `0008_jobrun` (new file, no committed migration edited). `run_daily` writes `JobRun("run_daily")` via `update_or_create` after `generate_due` returns, including when some rules failed (the job did run); not when it aborted on bad `--today`. Service `services/recurring.last_run(now)`-free helper `job_status()` returns `last_run_at | None` (services never read the clock).
4. `GET groups/{id}/recurring/status/` → `{last_run_at: datetime|null}` via `GroupScopedView`. URL declared before `recurring/<int:rid>/` is irrelevant (int converter), but registered next to the other recurring paths.
5. `e2e_reset --with-recurring-run`: after the normal seed, runs `generate_due(today)` for the rule(s) the flag seeds (a monthly "Rent" rule in Home starting on the 1st of the current month, so one expense is created) and writes `JobRun`. Without the flag the fixture is unchanged, so 011–013 e2e stay as they are.
`make schema` regenerates `schema.json`/`types.ts`; `docs/api.md` rows added.

**Frontend** (display and input parsing only; schedule maths mirrored for the preview, nothing stored).
- `src/lib/recurrence.ts`: `nextOccurrences(rule, from, n)` mirroring `next_occurrence`/`first_occurrence` on plain `YYYY-MM-DD` strings (no `Date` parsing through UTC): month-length clamp from the rule's own day each time (Jan 31 → Feb 28 → Mar 31), yearly with Feb-29 → Feb 28 in non-leap years. `describeRule(rule)` → "monthly on the 1st" / "yearly on 14 Mar".
- `src/pages/Recurring.tsx` (`/g/:id/recurring`): list (description, amount via `formatCents`, schedule text, next date, payer name, split summary, **Paused** badge as text); "+" opens the rule sheet. Row actions: Edit, Pause/Resume, Skip next (confirm shows the exact date being skipped = the row's `next_date`), Delete (confirm; copy states past expenses stay). Errors from the API render inline from `detail`.
- `src/pages/RuleSheet.tsx` (uses `Sheet`): reuses the 012 form pieces (amount, description, category, who paid, who for → `expenseBody` split builders) plus Frequency (Monthly | Yearly), day of month (monthly) or date (yearly), start date, optional end date. A preview line "Next: d1, d2, d3" computed by `nextOccurrences` from the form values (start date is the `from`) before Save. Edit sends PATCH with only changed fields; schedule changes are sent with the fields the API already requires.
- `Expenses.tsx`: rows with `recurring_rule != null` show a repeat icon (`aria-label="Created by a recurring rule"`) linking to `/g/:id/recurring#rule-<id>` which scrolls to and highlights the rule. 
- `Settings.tsx`: line "Recurring expenses are created by the daily job; last run: <date | never>" from `recurring/status/`.
- Layout rules from 011/012 stay; no horizontal scroll at 390 px.

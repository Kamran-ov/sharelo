# Plan 008 — Home analytics rollup: linked sub-groups into the main group

Ticket: `tickets/008-home-rollup.md` · risk: risky (money, identity, conversion)

## Current state
- `backend/ledger/services/analytics.py` (005) has the single-group functions `spending_by_member`, `spending_by_category`,
  `spending_by_month`, `spending_by_member_and_category`, built on private helpers `_splits_in_range` (inclusive dates, deleted
  excluded) and `_category_key(level)` (level 1 rolls child into parent). Spending = `ExpenseSplit.owed_cents`. Not already done:
  there is no `home.py` and nothing converts across groups.
- `backend/ledger/models.py`: `GroupLink(profile, sub_group, main_group, active)` unique on (profile, sub_group); `Member.profile` nullable
  with a DB constraint of one member per profile per group; `Group.currency`.
- `backend/ledger/services/rates.py`: `convert(cents, date, from, to)` returns early (no query) when currencies match, raises
  `LedgerError("no_rate")` when a foreign rate is missing or older than 7 days.
- `backend/ledger/services/groups.py` (006): `create_group`/`join_group_by_token` create links automatically; `move_debt_to_home` writes
  a twin pair of `Settlement` rows. Settlements are never queried by analytics.

## Proposal
New read-only module **`ledger/services/home.py`**, integer cents only, no writes. All functions take
`(main_group, date_from, date_to, trips="lines"|"spread")` where the ticket lists `trips`; any other value → `LedgerError("invalid_trips")`.

**Who contributes.** A "linked profile" for `main_group` is a profile that (a) has a `Member` in `main_group` and (b) has a
`GroupLink(main_group=main_group, active=True)` to the sub-group. For each sub-group, only splits of that profile's own `Member` in it
count. Consequences, all from the query filters and none from special cases:
trip guests (`profile IS NULL`) never match; an inactive link contributes nothing; a trip member whose link points at a *different* main
group never matches this one; partner A's active link rolls in A's trip shares even if B's link is inactive.
Main-group shares are taken as they are, via the existing `analytics.*(main_group, ...)` functions (members without a profile, such as a guest of Home,
contribute main-group shares only; same as analytics today).

**Conversion.** For every linked sub-group, one aggregate query over `analytics._splits_in_range(sub_group, ...)` filtered to the linked
profiles' member ids, grouped by `(expense__date, <the dimension>)`. Each aggregate row is converted once with
`rates.convert(total, date, sub_group.currency, main_group.currency)`, then summed in Python. Rate lookups use the expense date, never today.
Same-currency sub-groups never touch the rates table. `LedgerError(no_rate)` propagates.

**Functions**
- `home_spending_by_member() -> {main_member_id: cents}`: `analytics.spending_by_member(main_group)` plus, per profile, its converted trip shares.
  Trip profile → Home member id comes from one query (`Member` of `main_group` with a profile).
- `home_spending_by_category(level=1|2) -> {key: cents}`, key is a `category_id` or `("trip", group_id)`. `trips="lines"`: one pseudo-row per linked
  sub-group that has spending in range (omitted when 0); `level` applies to main-group rows only. `trips="spread"`: trip aggregates are grouped by
  `analytics._category_key(level)` and added to the real category ids.
- `home_spending_by_month() -> {"YYYY-MM": cents}`: trip aggregates grouped by date, converted, bucketed by the date's month in Python (same
  bucketing as `TruncMonth`: the date given, no time zone). `trips` has no effect on the numbers here but is accepted for a uniform signature.
- `home_trip_breakdown(main_group, trip_group, date_from, date_to, level=1) -> {trip_member_id: {category_id: cents}}`, converted into the main
  currency, linked members only (so it sums to that trip's line). A `trip_group` with no active link into `main_group` → `LedgerError("trip_not_linked")`.
- `linked_trips(main_group) -> list[LinkedTrip]` (`group_id`, `name`, `currency`; frozen dataclass, one query, active links only): gives the UI the
  names behind the `("trip", group_id)` keys without putting non-numbers into the totals dicts.

Move-to-Home settlements are never queried, so they cannot appear.

## Edge cases
- Rounding: conversion happens once per (date, dimension) aggregate, half-even. Same-currency trips are exact, so lines and spread always agree for them.
  For a foreign trip, lines (aggregate per date) and spread (aggregate per date and category) can differ by rounding, at most 1 cent per extra aggregate row.
  Documented in the module docstring; the acceptance fixture has one Tokyo expense so it is exact there.
- Profile in the trip but with no Member in Home: not linked, contributes nothing (a link row alone is not enough).
- Both partners linked to the same trip: each contributes only their own member's shares; nothing counted twice.
- Sub-group with zero expenses in range: no query cost beyond its aggregate, no row.
- Empty range or `date_from > date_to`: empty trip part; main part follows `analytics` behaviour.

## Proposal

### Service (rule 8: the view only parses and calls)
New `backend/ledger/services/analytics_report.py`. It calls the existing functions (no new money arithmetic, no `/ 100`) and only resolves labels and orders rows:
- `Row = {"key": str, "label": str, "cents": int}`; nested rows add `"rows": [Row]`.
- `group_report(group, date_from, date_to, by, level) -> dict` → `{currency, from, to, rows}`.
- `home_report(main_group, date_from, date_to, by, trips, level) -> dict` → same shape.
- `trip_report(main_group, trip_group, date_from, date_to, level) -> dict` → same shape, nested (member → category), `currency` = Home's. It passes `date_from`/`date_to` straight to `home_trip_breakdown` (the service filters; the view never does), so the response's `from`/`to` are the range the numbers cover.
- `check_range(date_from, date_to)` and `default_range(today)`; `by` ∈ `member|category|month|member_category`, else `LedgerError("invalid_by")`.

Keys and labels (all keys are strings so one shape fits every `by`):
| by | key | label | order |
|---|---|---|---|
| member | `"<member_id>"` | `display_name` | member id; every member listed, 0 included (as the service returns) |
| category | `"<category_id>"` | level 1: name; level 2: `"Parent › Child"` (root category: its name) | cents desc, then key |
| category, Home `trips=lines` | `"trip:<group_id>"` for a trip line | trip group name | mixed with categories, same order |
| month | `"YYYY-MM"` | same as key | ascending; months with data only (no zero-filling — a chart concern) |
| member_category | outer member as `member`, inner as `category`; outer `cents` = sum of its inner rows | | outer by member id; members with no spending omitted (as the service returns) |

Labels come from at most one `Member` query and one `Category` query (`select_related("parent")`) per call, plus Home's `linked_trips` (one query) only in `trips=lines`.

### Defaults and range (ticket)
- `from`/`to` omitted → the current calendar month of `today()` (first to last day). One given alone → the other defaults to the same month bound of today (`from` → first of current month, `to` → last of current month); assumed below.
- A `from` or `to` that is not a valid ISO date (`2026-13-01`, `foo`, empty `?to=`) → 400 `invalid_date`, on every analytics route.
- `from > to` → 400 `invalid_range`. Range longer than 5 years → 400 `range_too_long`: allowed iff `to < add_years(from, 5)` (29 Feb + 5 years → 28 Feb), so 2021-01-01…2025-12-31 passes and …2026-01-01 is refused.
- `level` default 1 (1|2, else 400 `invalid_level`); `by` default `category`; `trips` default `lines` (else 400 `invalid_trips`). `level` is ignored for `member`/`month`; `trips` only changes `by=category` (that is what the service does: member and month totals are the same in both modes).

### Endpoints (`ledger/api/views.py`, `urls.py`)
- `GET groups/{id}/analytics/?from&to&by&level` → `GroupAnalyticsView(GroupScopedView)` → `group_report`. Guests allowed (base class); outsider/missing → 404. Includes guests' shares (`profiles_only=False`): the group view is the group's own spending.
- `GET home/analytics/?from&to&by&trips&level` → `HomeAnalyticsView`: `require_profile` (guest or anonymous → 401 `not_authenticated`); profile without `main_group` → 404 `not_found`; else `home_report(profile.main_group, …)`. `by=member_category` → 400 `invalid_by` (no Home service for it; assumed below).
- `GET home/analytics/trip/{group_id}/?from&to&level` → `HomeTripAnalyticsView`: same 401/404 rules; `trip_not_linked` (incl. a non-existent id) is re-raised as 404 `not_found`, so the route does not reveal other groups.
- `no_rate` from a Home call stays 400 `no_rate` (existing mapping).
- Serializers `AnalyticsRowSerializer` (with optional nested `rows`) and `AnalyticsSerializer` for the schema; query params documented with `OpenApiParameter`. `make schema` regenerates `frontend/src/api/schema.json` (no frontend code uses it in this ticket).

### Query bound
Group analytics: constant (session/auth + group + membership + 1 service query + ≤2 label queries), independent of member and expense count. Home: constant + per linked sub-group (≤1 cell aggregate + ≤1 rate query, per `home.py`), plus the label queries. Asserted as invariance and per-trip growth (below), not as hard-coded totals.

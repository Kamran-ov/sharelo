Ticket: `tickets/018-share-summary.md` · risk: normal

## Current state
Not done. Nothing in the repo shares or copies anything (`grep -ri "clipboard\|navigator.share" frontend/src` is empty).
- Backend: `GET groups/{id}/balances/` (`backend/ledger/api/views.py:BalancesView`) already returns `nets`, `transfers` (from `services/balances.py:simplify_debts`) and `members[]` built by calling `balances.member_summary` once per member — each call runs the paid/owed/settlement queries again, so that view is O(members) in queries. - e2e: `frontend/e2e/balances.spec.ts`, helpers `seedExpense`, `apiCall`, `romeMembers`, `owes`, `shot`, `expectNoHorizontalScroll`.

## Proposal

### Backend (rule 8: logic in services, view only calls)
1. `services/balances.py: member_summaries(group) -> dict[int, dict[str, int]]` — `{member_id: {paid, owed_share, net}}` for every member, from **one** pass of `_paid_and_owed` + `_settlement_flows` (same arithmetic as `member_summary`, which stays and is unchanged). Calls `_check_balanced` on the nets.
2. New `services/summary.py: group_summary(group) -> dict`:
   - `nets = net_balances(group)`, `transfers = simplify_debts(nets)` — the existing functions, not a copy.
   - `per_member`: for every member ordered by id: `{member_id, display_name, paid, owed_share, net}` from `member_summaries`; `net` must equal `nets[member_id]` (asserted in tests, not re-derived).
   - `total_spent_cents`: `Sum("amount_cents")` over the group's non-deleted expenses (default manager), `0` when none. All expenses count, `personal` included (it is spending under FACTS; it only has no balance effect). Equals `sum(owed_share)` because splits sum to total (hard rule 3) — tested.
   - `recent_expenses`: the last 10 non-deleted expenses ordered `-date, -id` (same order as the list endpoint), each `{id, date, description, amount_cents, paid_by: [member_id, …]}` (payers ordered by member id, from one `prefetch_related("payers")`).
   - Constant query count independent of member and expense count.
3. `GET groups/{id}/summary/` → `GroupSummaryView(GroupScopedView)`:
   `{group: {id, name}, currency, total_spent_cents, per_member: [...], transfers: [{from_member, to_member, amount_cents}], recent_expenses: [...]}`. Serializers in `ledger/api/serializers.py` for the schema only. Read-only, so no CSRF concerns. Outsider/missing group → 404 via the base class.
4. `make schema` regenerates `frontend/src/api/schema.json` and types; `docs/api.md` gains the row.

### Frontend (formatting only; every number comes from the server, no money arithmetic)
1. `src/lib/summaryText.ts`:
   - `summaryLines(s: GroupSummary): string[]` — the single source for both text and image:
     ```
     Rome trip — total 1240.00 EUR
     (blank)
     Bea pays Alice 82.50
     Carl pays Alice 10.00
     (blank)
     Last expenses:
     12 Nov Dinner 60.00 (Alice)
     11 Nov Taxi 24.50 (Bea)
     ```
     Header: `${group.name} — total ${formatCents(total)} ${currency}`. Transfers: `${name(from)} pays ${name(to)} ${formatCents(amount)}`, in server order; when there are none, the single line `All settled up.`. Recent: date as `D Mon` from a fixed English month table (no `toLocaleString`, deterministic in tests and on every phone), description, amount, payers' names joined with `, `. Section omitted when there are no expenses. Names come from `per_member[].display_name` (no "you": the reader is someone else).
   - `summaryText(s) = summaryLines(s).join("\n")`.
2. `src/lib/summaryImage.ts: renderSummaryPng(lines: string[]): Promise<Blob>` — draws the lines on a `<canvas>` (white card, 2× scale, 16px system font, header bold, fixed width 720 px, height from line count) and returns `canvas.toBlob("image/png")`. Draw-only, no layout logic worth unit testing; covered by e2e and the committed screenshot.
3. `src/lib/share.ts`: `shareText(text)`: `navigator.share({text})` when available → `"shared"`; else `navigator.clipboard.writeText(text)` → `"copied"`. `shareImage(blob, filename)`: `navigator.canShare?.({files:[file]})` → `navigator.share({files:[file]})`; else download via an `<a download>` object URL → `"downloaded"`. A user cancelling the share sheet (`AbortError`) is not an error: no toast.
4. `pages/Balances.tsx`: a **Share** button in the header area opens `ShareSheet` (uses `Sheet`) with two buttons, "Share as text" and "Share as image". The summary is fetched by `useQuery(["summary", group.id])` when the sheet opens, and the PNG is rendered as soon as data arrives — so the share call itself runs synchronously inside the tap (iOS Safari drops `navigator.share` after an `await` that outlives the user gesture). Buttons are disabled until data (and, for the image, the blob) is ready. Toasts: "Copied to clipboard", "Image downloaded"; a share failure other than cancel shows "Could not share". The summary query is invalidated by the same mutations that invalidate `balances` (settle, undo, move-to-home).
5. Layout: no horizontal scroll at 390 px, buttons ≥ 44 px tall (011/012 rules).

## Open questions
- Assumed: amounts use the existing `formatCents` without thousands grouping ("1240.00", not the ticket example's "1,240.00"), because the ticket says to reuse `formatCents`; grouping can come with the visual design ticket.
- Assumed: `total_spent_cents` includes `personal` expenses (all live expenses), consistent with analytics counting owed shares.
- Assumed: "one tap" is the Share button opening a two-option sheet (text / image); sharing itself is the second tap. A single button that shares text and image together would hide the clipboard fallback for text.
- Assumed: dates in the text use `D Mon` with an English month table; no year, since the last 10 expenses are recent.

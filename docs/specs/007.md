# Plan 007 — Recurring rules and the daily job

Ticket: `tickets/007-recurring-rules.md` · risk: risky (money, a job that writes expenses unattended, migration)

## Current state

  `Source.RECURRING` exists. Migration `0001_initial` created the stub table (empty everywhere: nothing creates rules).
- `services/expenses.py`: `create_expense_from_preset(group, preset=, payer_id=, params=, ..., source=, external_id=, recurring_rule=)`
  already builds splits and writes expense + payers + splits in one transaction; `_validate` rejects payers/splits that are not
  members of the group; the unique `(source, external_id)` constraint raises `LedgerError("duplicate_external_id")`.
- `services/splits.py`: `split_for_preset` and the `params` shape (`CategoryDefault.split_params`) are reused as is.
- `services/rates.py`: `fetch_ecb_rates()` upserts rates; `management/commands/fetch_rates.py` is the only command.
- No `services/recurring.py`, no `run_daily`, no README "Daily job" section. Not already done.

## Proposal
**Model** (`ledger/models.py`, new migration `0006`, never edit 0001): `RecurringRule` gains `description`, `amount_cents`,
`payer` FK(Member, PROTECT, `related_name="+"`), `split_type` (SplitType choices), `split_params` JSON default `{}`, `category`
FK(Category, PROTECT), `frequency` (`monthly`/`yearly`, TextChoices), `day_of_month`, `month` (null; yearly only), `start_date`,
`next_date`, `end_date` (null), `paused` bool, `created_at`, `updated_at`, `deleted_at`. Default manager hides deleted rows,
`all_objects` shows them (same pattern as `Expense`). CHECKs: `amount_cents > 0`; `day_of_month` 1–31; `month` null iff monthly,
1–12 iff yearly. Existing rows: none, so non-null columns are added with a throwaway default dropped in the same migration
(table is empty; noted, no data step needed).

**`ledger/services/recurring.py`** (integer cents only; `LedgerError` only; no logic in views/models)
- `next_occurrence(after, rule) -> date` — pure: first occurrence strictly after `after`. Day clamped to the month length
  (31 → Feb 28/29 → Mar 31); yearly Feb 29 → Feb 28 in non-leap years.
- `first_occurrence(on_or_after, rule) -> date` — pure helper (occurrence on that day counts); used for `start_date`, `resume_rule`.
- `create_rule(group, **fields)`: validates (amount > 0, payer belongs to group, frequency/month/day rules, preset name via
  `split_for_preset` dry-run on the group's members so a bad `split_params` fails at save, not at 3 a.m.), sets
  `next_date = first_occurrence(start_date)`.
- `update_rule(rule, today=None, **fields)`: same validation; edits the rule only, past expenses are never touched. Final rule: amount,
  description, category, payer, split and `end_date` edits leave `next_date` alone; if `day_of_month`, `month`, `frequency` or `start_date`
  changes, `today` is required (missing → `LedgerError("today_required")`; services never call `date.today()`) and
  `next_date = first_occurrence(max(rule.next_date, today))` under the new schedule, so an edit mid-month never bills the same month twice.
- `delete_rule(rule)`: sets `deleted_at`; expenses keep `recurring_rule`.
- `pause_rule`, `resume_rule(rule, today)` (next_date = first occurrence on/after today; paused months not back-filled),
  `skip_next(rule)` (next_date = next_occurrence(next_date); no expense).
- `generate_due(today) -> GenerateResult(created: list[Expense], failed: list[tuple[rule_id, code]])`: for each active rule
  (not deleted, not paused) loop while `next_date <= today` and (`end_date` is None or `next_date <= end_date`):
  `create_expense_from_preset(..., source="recurring", external_id=f"rule:{id}:{next_date.isoformat()}", recurring_rule=rule,
  date=next_date, currency=group.currency, params=split_params)`, then advance `next_date`, both in one `transaction.atomic`
  per occurrence; the rule row is locked with `select_for_update` for the occurrence so two concurrent runs cannot both create it.
  A `duplicate_external_id` on an occurrence means it already exists: advance `next_date` and continue (that is what makes a
  half-recovered rule self-heal). Any other `LedgerError`/exception stops that rule only (recorded in `failed`), others continue.
  Past `end_date`: no more expenses (rule stays, `next_date` is left alone).
- Splits use all current members of the group when the preset needs `member_ids` (same default as `create_expense_from_preset`).

**Command `run_daily [--today YYYY-MM-DD]`**: step 1 `fetch_ecb_rates()` in try/except (logged, does not stop step 2);
step 2 `generate_due(today)`; prints `rates upserted N / expenses created N / rules failed N`; `today` defaults to `timezone.localdate()` (never `date.today()`), same line in the README; exits non-zero (`CommandError` /
`sys.exit(1)`) only when a rule failed. Rate-fetch failure alone is exit 0 (rates are retried tomorrow; the 7-day lookback absorbs it).

**README**: "Daily job" section with the command and an example cron line. No scheduler in the repo.

## Implementation notes
- The `duplicate_external_id` catch sits outside each occurrence'"'"'s `transaction.atomic()` block (it is a savepoint under test transactions; catching inside would leave the next statement aborted).
- The module docstring avoids ` / ` and `round(` so the no-float/decimal source scan passes.
- `generate_due` returns `GenerateResult(created, failed)` instead of the ticket'"'"'s `list[Expense]`; listed under Plan changes in the REPORT.

## Edge cases
- Rule created with `start_date` in the past → catch-up on first run (intended); with `start_date` in the future → nothing yet.
- Day 31 rule after clamped Feb: next is computed from the *rule's* day (Mar 31), never from the clamped date (no drift to 28).
- `--today` in the past/future is only for tests and ops; a future `--today` creates future-dated expenses (documented, not blocked).
- Rule with `end_date < start_date` → refused at save. Group with one member: `equal` works, `full_for_other` without `other_id` refused at save.
- Foreign-currency rules are not supported (amount is in group currency, per ticket); no rate lookup in generation.
- Cron overlap / double-run: row lock + unique `external_id`.

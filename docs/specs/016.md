# Plan 016 — Laptop Docker test run sees the whole repo; faster test hashing

Ticket: `tickets/016-docker-test-paths.md` · risk: normal

## Current state
Not done.
- `docker-compose.yml` service `backend` mounts only `./backend:/app` (workdir `/app` from `backend/Dockerfile`). `backend/tests/test_prod_settings.py:10` computes `ROOT = Path(__file__).resolve().parents[2]`, which inside the container is `/` (`/app/tests/test_prod_settings.py` → `/`), so `ROOT / "compose.prod.yml"`, `deploy/crontab`, `scripts/`, `Makefile` are missing. The same applies to any other test reading `frontend/src/api/schema.json` or repo-root files.
- `Makefile`: `USE_DOCKER=1` already routes `test-frontend` through `docker compose run --rm frontend npm test`, and `frontend/package.json` already has `"test": "vitest run"` (never watch). So the frontend half of the scope holds today; the plan adds a guard test for it rather than a change.
- `backend/pyproject.toml` pytest uses `DJANGO_SETTINGS_MODULE = "sharelo.settings"`; `sharelo/settings.py` sets no `PASSWORD_HASHERS`, so tests use PBKDF2 (baseline: `make test-backend` = 405 passed in 123.67 s in this cloud session).

## Proposal
1. **Repo visible in Docker.** In `docker-compose.yml` service `backend`: volume `.:/repo` replaces `./backend:/app`, and `working_dir: /repo/backend`. Then `Path(__file__).parents[2]` is `/repo` exactly as on a checkout, so no test changes its ROOT logic. The dev `runserver` command works unchanged from that workdir. The image's `COPY . .` into `/app` stays for non-compose builds. `frontend` service is untouched (its tests read only `frontend/`).
2. **Frontend always terminates.** No change to `package.json`; a backend-side test (below) pins `"test": "vitest run"` so a switch to watch mode is caught.
3. **Fast hasher only under pytest.** New `backend/sharelo/settings_test.py`: `from .settings import *` then `PASSWORD_HASHERS = ["django.contrib.auth.hashers.MD5PasswordHasher"]`. `backend/pyproject.toml` points pytest at it. `sharelo/settings.py` and everything prod/e2e/manage.py/wsgi use stays unchanged. Subprocess tests in `test_prod_settings.py` set `DJANGO_SETTINGS_MODULE=sharelo.settings` explicitly, so they exercise the real prod module.
4. Docs: README test section and `CLAUDE.md` §5 command table note that Docker mounts the whole repo at `/repo`.

Paired with `test_pytest_settings_use_md5_hasher` (in-process `settings.PASSWORD_HASHERS[0]` is MD5) so the fast path is proven active, and a login test still passes under it.

- Regression guard: all 405 existing tests stay green; count becomes 405 + the new ones.

# Plan 004 — Exchange rates and conversion to group currency

Ticket: `tickets/004-currency.md` · risk: normal (touches money conversion, so the rounding cases are pinned with numbers below)

## Current state
- `Expense.rate_used` (Decimal 18,8, nullable), `original_amount_cents`, `original_currency` exist in `ledger/models.py`. There is no `ExchangeRate` model, no `ledger/services/rates.py`, no management command (`backend/ledger/management/` does not exist).
- `expenses.create_expense` takes `amount_cents` plus optional `original_*`/`rate_used`; `_validate` only checks that the three originals come together, and `_original_fields` writes `rate_used=1` for same-currency expenses. Nothing computes a conversion: a caller would have to pre-compute `amount_cents` itself. `create_expense_from_preset` forwards `**rest` to `create_expense`.
- `Expense.currency == group.currency` is enforced (`currency_mismatch`). The work is not already done.

## Proposal
**Model** `ExchangeRate(date, currency, rate_to_eur Decimal(18,8))`, unique `(date, currency)`, CHECK `rate_to_eur > 0`; new migration `0003_exchangerate` (existing migrations untouched). Stored as ECB publishes it: units of `currency` per 1 EUR (USD 1.10 means €1 = $1.10). EUR itself is never stored; it is implicitly 1.

**`ledger/services/rates.py`** (the only module besides `expenses.py` that may hold a Decimal, for rates only; money in and out stays `int`):
- `parse_ecb_xml(text) -> dict[date, dict[str, Decimal]]` — pure; parses the ECB `Cube/Cube[@time]/Cube[@currency,@rate]` format (handles both daily and 90-day/hist XML).
- `fetch_ecb_rates(since=None) -> int` — the one network function. Downloads `eurofxref-hist.xml` (the ticket names the zip; the zip's inner file is the same XML, so we fetch `eurofxref-daily.xml` when `since` is None or within 90 days, `eurofxref-hist-90d.xml` otherwise, `eurofxref-hist.xml` for older), parses, upserts with `bulk_create(update_conflicts=True)` in one transaction (re-runnable), returns rows written. Tests stub this one function / its download helper.
- `rate(date, from_currency, to_currency) -> Decimal` — units of `to` per 1 `from`. Same currency → `Decimal(1)` with no DB access. Otherwise `eur_per_from / eur_per_to` where each leg uses the latest `ExchangeRate` on or before `date`, no older than 7 days (`date - 7 <= row.date <= date`); EUR leg = 1. Missing leg → `LedgerError("no_rate", "<CCY> on <date>")`. Result quantized to 8 dp (matches `rate_used`).
- `convert(amount_cents: int, date, from_currency, to_currency) -> int` — `amount * rate`, `ROUND_HALF_EVEN` to an integer (sign-symmetric). The computation uses the quantized 8-dp rate, so the stored `rate_used` reproduces `amount_cents` exactly.

**`fetch_rates` command** (`ledger/management/commands/fetch_rates.py`): `--since YYYY-MM-DD` (invalid date → `CommandError`), calls `fetch_ecb_rates`, prints the row count.

**Hook in `expenses.py`**: new `create_expense` behaviour keyed on `original_currency`, without breaking the current callers:
- New helper `resolve_foreign_amount(group, date, original_amount_cents, original_currency, rate_used=None) -> tuple[int, Decimal]` in `rates.py`: if `original_currency == group.currency` → `(original_amount_cents, 1)`; else uses the explicit `rate_used` if given (override, for currencies the ECB does not publish) else `rate(date, original_currency, group.currency)`; returns `(convert via that rate, rate)`.
- `create_expense_from_preset` gains: when `original_amount_cents` and `original_currency` are given and `amount_cents` is omitted (`None`), it calls the helper first, then splits the *converted* amount, so payers and splits sum to the converted total by construction. `create_expense` itself keeps requiring explicit, consistent numbers (`amount_cents` given alongside originals is still accepted as before) and gains one extra check: if originals are given with `original_currency != group.currency`, `rate_used` is required (already `incomplete_original`). `update_expense` is unchanged (out of scope: re-conversion on edit).

## Tests
`backend/tests/test_ledger_rates.py` (DB, network stubbed), fixture `backend/tests/fixtures/ecb_daily.xml` (real ECB format, trimmed to ~5 currencies over 3 dates incl. a Friday) and a second `ecb_hist_snippet.xml` exercising multiple `Cube time=` blocks.
- `test_usd_expense_converts_at_that_days_rate` — **KEY**: USD 1.10 on 2026-03-02, $60 (6000) in a EUR group via `create_expense_from_preset` → `amount_cents == 5455`, `rate_used == 0.90909091`, `original_amount_cents == 6000`, payers/splits sum 5455; £10 at GBP 0.85 → 1176. Removing the hook leaves `amount_cents` unset/wrong and this fails.
- `test_cross_rate_goes_through_eur` — USD→GBP equals `(1/1.10)*0.85` within 1e-8; twin: `test_same_currency_rate_is_one_without_lookup` (no rows needed).
- `test_weekend_uses_previous_friday_rate` (Saturday and Sunday) paired with `test_date_with_no_rate_in_previous_7_days_raises_no_rate` (boundary: exactly 7 days old passes, 8 days old raises).
- `test_explicit_rate_override_is_stored_and_used` with twin `test_unknown_currency_without_override_raises_no_rate`.
- `test_convert_rounds_half_even` — pinned: 5 cents at rate 0.5 → 2, 7 cents at 0.5 → 4, negative symmetric; `test_convert_returns_int`.
- `test_parse_ecb_fixture_real_format` — daily and hist fixtures yield the expected dates/currencies/Decimals.
- `test_fetch_is_idempotent_and_updates_changed_rates` — stubbed download, run twice → same row count; changed rate on second run is updated.
- `test_fetch_rates_command_since_validates_date` — bad date errors, good date calls fetch with it.
- `test_unique_rate_per_date_and_currency` — model constraint refuses a duplicate, accepts the same currency on another day.
- `test_rates_module_money_is_integer` — `convert` return type is `int`; no `float(` in the module source (CLAUDE.md §2).

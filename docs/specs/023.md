## Proposal

### 1. One token file, one theme file
- `frontend/src/styles/tokens.css`: byte-identical copy of `docs/design/tokens.css`. Copying is by hand (`cp`), stated in both READMEs; the test in §Tests keeps them identical.
- `frontend/src/styles/theme.css` (replaces the body of `index.css`, which becomes `@import "./styles/theme.css";` or `main.tsx` imports theme directly):
  ```css
  @import "tailwindcss";
  @import "./tokens.css";
  @import "./fonts.css";
  @theme { --color-*: initial; --font-*: initial; }      /* drop Tailwind's default palette + font stacks */
  @theme inline {
    --color-primary: var(--brand-primary);  --color-primary-hover: var(--brand-primary-hover);
    --color-highlight: var(--brand-highlight); --color-highlight-soft: var(--brand-highlight-soft);
    --color-owed: var(--money-owed); --color-owe: var(--money-owe); --color-owe-soft: var(--money-owe-soft);
    --color-neutral: var(--money-neutral);
    --color-ground: var(--surface-ground); --color-card: var(--surface-card); --color-sunken: var(--surface-sunken);
    --color-line: var(--border); --color-line-subtle: var(--border-subtle);
    --color-ink: var(--text); --color-muted: var(--text-muted); --color-on-primary: var(--text-on-primary);
    --color-overlay: var(--overlay); --color-danger: var(--danger); --color-danger-soft: var(--danger-soft);
    --color-transparent: transparent; --color-current: currentColor;
    --font-heading: var(--font-heading); --font-body: var(--font-body);
    --radius-sm: var(--radius-sm); --radius-md: var(--radius-md); --radius-card: var(--radius-lg);
    --radius-hero: var(--radius-xl); --radius-sheet: var(--radius-sheet); --radius-pill: var(--radius-pill);
    --text-xs: var(--text-xs); … --text-amount: var(--text-amount);
    --shadow-fab: var(--shadow-fab); --shadow-segment: var(--shadow-segment);
  }
  body { background: var(--surface-ground); color: var(--text); font-family: var(--font-body); }
  ```
  `@theme inline` makes each utility emit `var(--brand-primary)` directly, so a runtime override of a token (the KEY e2e) reaches every element. `--color-*: initial` means `bg-emerald-600` generates **no CSS at all**: a forgotten old class shows as uncoloured, never as a second palette. (`--color-*: initial` must not also kill the names `transparent`/`current`; re-declared above.) Exact names listed above are the only colour/font/radius names components use; the ticket's `primary, highlight, owed, owe, ground, card, ink, muted` are all present, `border` becomes `line` because `border-border` is unreadable.
- Dark mode is entirely the tokens' `@media (prefers-color-scheme: dark)` block; no `dark:` variants anywhere (guard test, below).

### 2. Fonts, self-hosted
- `@fontsource/inter` and `@fontsource/space-grotesk` (5.3.0, OFL-1.1) as **devDependencies only**, used as the source of the files: `scripts/brand-assets.mjs` copies the latin-subset woff2 for Inter 400/500/600 and Space Grotesk 500/600/700 into `frontend/public/fonts/`, plus `OFL.txt` for each family. The woff2 files are committed; nothing is fetched at build or runtime.
- `src/styles/fonts.css`: six `@font-face` rules, `font-display: swap`, `src: url("/fonts/…woff2") format("woff2")`. The family names `"Inter"`/`"Space Grotesk"` appear in `@font-face { font-family: … }` here — this file is the one allowed exception besides `tokens.css` for the *declaration* keyword (see guard test; the families' use in `font-family:` stacks stays tokens-only). Assumed: the guard allows `font-family` inside `@font-face` blocks of `fonts.css` only; everything else that names a family fails.
- `workbox.globPatterns` gains `woff2` (the plugin default is `**/*.{js,css,html}`), so `offline.html` renders in the brand fonts with no network. `index.html` stays excluded as in 015.

### 3. Logo, favicon, PWA icons
- `src/components/Logo.tsx`: inline `<svg viewBox="0 0 48 48">` with the exact geometry of `docs/design/logo-mark.svg` (rect rx 14, the two half-disc paths, the divider line) whose fills are `var(--brand-primary)`, `var(--text-on-primary)`, `var(--brand-highlight)` and the divider stroke `var(--brand-primary)`. Because the dark tokens give exactly the dark mark's colours (#2BB3A6 / #0F2E33 / #CFF3EC), the one component *is* `logo-mark-dark.svg` under dark mode, with no second component and no hex in `src/`. A unit test proves that mapping (below). Props: `size` (default 32), `wordmark` (boolean): when true renders `<span class="font-heading font-semibold tracking-[-0.02em]">sharelo</span>` beside the mark, lower case, text not image.
- Used in: the `GroupShell` header (mark 32, group name + "CUR · members" subtitle per the Expenses board) and the Login page (mark 48 + wordmark). Groups and Join pages get the mark + wordmark header too (same component).
- Icons: `scripts/make-icons.mjs` is replaced by `scripts/brand-assets.mjs` (`make icons` → `cd frontend && node scripts/brand-assets.mjs`): reads `docs/design/logo-mark.svg`, rasterises via Playwright Chromium (existing approach, no new rasteriser) to `public/icons/icon-192.png`, `icon-512.png`, and `icon-maskable-512.png` (the mark scaled to the 80 % safe zone on a full-bleed `--brand-primary` square, colour read from `tokens.css` by the script), plus `public/favicon.svg` (copy of `logo-mark.svg`). It also copies the fonts (§2). Placeholder `icon.svg` / `icon-maskable.svg` are deleted. Output committed; nothing generated at build.
- `index.html`: `<link rel="icon" href="/favicon.svg" type="image/svg+xml">`; `theme-color` meta and the manifest's `theme_color`/`background_color` are **read from `tokens.css` at build time** by a 10-line helper in `vite.config.ts` (`lightToken("--brand-primary")`, parses the `:root` block), and injected into `index.html` by a tiny `transformIndexHtml` plugin. Result: `#0B6F6A` / `#F4F9F8`, and changing the token changes them on the next build, with no second literal.
- `public/offline.html` must render with no network and no JS, so it cannot use the bundled CSS. To keep one source, it gets `<link rel="stylesheet" href="/offline.css">`; `scripts/brand-assets.mjs` writes `public/offline.css` = the exact content of `tokens.css` + a few lines of layout using only `var(--…)`. Precached with `offline.html`. The tokens-copy test also asserts `offline.css` starts with `tokens.css`'s content, so it cannot drift.

## Tests

- **`test_no_colour_or_font_literal_outside_tokens`**: walks `src/**/*.{ts,tsx,css}` (excluding `src/styles/tokens.css`, `src/api/schema.json` is not matched by the glob) and fails, listing `file:line`, on: `#[0-9a-fA-F]{3,8}\b` colour hex, `rgba?\(`, `hsla?\(`, `oklch\(`, and any `font-family`/`fontFamily`/family name (`Inter`, `Space Grotesk`, `system-ui`, `sans-serif`, `serif`, `monospace`, `Helvetica`, `Arial`, `Roboto`) — except `font-family:` lines inside `src/styles/fonts.css` `@font-face` blocks. Paired success: the same scanner run over a fixture string with only `var(--brand-primary)` and `bg-primary` returns zero findings (proves it is not just failing on everything).
- **`test_no_tailwind_default_palette_or_dark_variant_classes`**: same walk, fails on `\b(bg|text|border|ring|outline|fill|stroke|from|via|to|divide|placeholder|caret|accent|decoration|shadow)-(slate|gray|zinc|neutral|stone|red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose|white|black)\b` and on `\bdark:`. Rationale: with the default palette removed those classes render nothing, so a leftover would be a silent unstyled element; a `dark:` variant would be a second source of dark colours. `neutral` is both a Tailwind palette name and our token: the palette alternative for `neutral` requires a `-<shade>` suffix (`text-neutral-500` fails, `text-neutral` passes). Success case: a fixture string with `text-neutral bg-primary border-line` yields zero findings.

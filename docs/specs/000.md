# Plan 000 — Repository scaffold

Ticket: `tickets/000-scaffold.md` · risk: normal

## Current state
- The repo holds only docs: `README.md` (two lines), `docs/PLAN.md`, `docs/REVIEW-LOG.md`,
  `tickets/*`, `.gitignore`. No `backend/`, `frontend/`, `Makefile`, compose file, CI or scripts.
- `.gitignore` lists `.venv/`, `node_modules/`, `__pycache__/`, `*.pyc`, `.env`, and also
  `.claude/settings.json` and `CLAUDE.md`. The ticket wants `CLAUDE.md` committed (see Open questions).
- The work is not already done.
- Environment seen while planning: Python 3.11, Node 22, `psql`, `pg_ctlcluster` and PostgreSQL 16
  binaries present; no `.github/`. Docker CLI exists but the ticket says the cloud has no daemon.

## Proposal
**Backend (`backend/`)**
- `requirements.txt` / `requirements-dev.txt` (Django 5.x, djangorestframework, `psycopg[binary]`,
  `pytest`, `pytest-django`, `ruff`), `pyproject.toml` (ruff + pytest config,
  `DJANGO_SETTINGS_MODULE=sharelo.settings`), `manage.py`, package `sharelo/`
  (`settings.py`, `urls.py`, `wsgi.py`, `asgi.py`).
- `settings.py`: `DATABASE_URL` parsed with stdlib `urllib.parse` (no extra dependency), default
  `postgres://sharelo:sharelo@db:5432/sharelo` (compose). Optional `TEST_DATABASE_NAME` env sets
  `DATABASES["default"]["TEST"]["NAME"]`. `SECRET_KEY`/`DEBUG`/`ALLOWED_HOSTS` from env.
  Installed apps: only Django defaults + `rest_framework`.
- `backend/tests/test_db.py`: the trivial test executes `SELECT version()` and `SELECT 1` through
  the Django connection and asserts the vendor is `postgresql`.

**Frontend (`frontend/`)**
- Vite + React + TS skeleton: `package.json`, `package-lock.json`, `tsconfig.json`,
  `vite.config.ts` (with vitest config), `index.html`, `src/main.tsx`, `src/App.tsx` ("Hello"),
  `src/App.test.tsx` (renders, finds "Hello"; `@testing-library/react`, `jsdom`).
  Scripts: `test` = `vitest run` (never watch mode), `build`, `lint` = `tsc --noEmit`.

**Compose** — `docker-compose.yml`: `db` (postgres:17, `pg_isready` healthcheck), `backend`
(`depends_on: db: condition: service_healthy`), `frontend`. Dockerfiles in `backend/` and `frontend/`.
The backend/frontend services run `sleep`-free commands (`python manage.py runserver`, `npm run dev`)
which are for the laptop only; no Makefile target or CI step calls them.

**`scripts/cloud-setup.sh`** (meant to be *sourced* so it can export `DATABASE_URL`):
installs PostgreSQL via apt if `pg_ctlcluster` is missing, starts the cluster with
`pg_ctlcluster <ver> main start` (a single command that daemonises itself, no `&`), waits via
`pg_isready -t 30` (built-in timeout, no loop), creates role/db `sharelo` idempotently
(`CREATE ROLE … ` guarded by a `\gexec` existence check), exports
`DATABASE_URL=postgres://sharelo:sharelo@localhost:5432/sharelo`. The script only handles the
database; Python and Node dependencies are installed by `make install`
(`pip install -r backend/requirements-dev.txt`, `npm ci`).

**Makefile** — `install`, `test-backend`, `test-frontend`, `test`, `lint`. With `USE_DOCKER=1`
each target runs through `docker compose run --rm …`; otherwise it runs directly against
`DATABASE_URL`. `lint` = `ruff check` + `ruff format --check` + `tsc --noEmit`.
Plain recipes, no loops; failing commands propagate non-zero exit.

**CI** — `.github/workflows/ci.yml` on `pull_request` (and push to `develop`): Postgres 17 service
container with health options, set up Python and Node, `make install`, `make lint`, `make test`
with `DATABASE_URL` pointing at the service. `timeout-minutes: 15` on the job.

**Docs/housekeeping** — `README.md` (5-command setup, test commands, `USE_DOCKER=1 make test`),
`CLAUDE.md` (stack, commands, workflow link, "money is integer cents, never floats", no
unbounded-command rule), `.env.example`, `.gitignore` additions (`.env`, `frontend/dist`,
`.pytest_cache`, `.ruff_cache`). `.claude/settings.json` is referenced in CLAUDE.md but not created
(it is gitignored and Kamran's).

`develop` already exists; `main` protection is a GitHub setting for Kamran, not code.

## Tests
- `backend/tests/test_db.py::test_database_is_postgres` — **KEY test**: asserts
  `connection.vendor == "postgresql"` and that `SELECT version()` mentions PostgreSQL. It fails if
  settings fall back to SQLite or the DB is unreachable. Proof: run it with `DATABASE_URL`
  pointed at `sqlite:///x` / wrong port and capture red, then restore.
- `backend/tests/test_settings.py::test_database_url_is_parsed` (legitimate-success pair):
  parser turns a full URL into the expected NAME/USER/HOST/PORT, and
  `::test_database_url_rejects_non_postgres_scheme` refuses `sqlite://` instead of silently using it.
- `frontend/src/App.test.tsx` — renders "Hello".
- Acceptance run: `scripts/cloud-setup.sh` then `make test` and `make lint`, output pasted in the PR.
- Script-safety check: a `grep` over Makefile, `scripts/`, `.github/` for `while|until|seq|sleep|watch|tail -f|nohup| &$`
  must come back empty (run once in the build; documented in the report).

## Documentation
README (setup + tests), CLAUDE.md, `.env.example`, comments in `cloud-setup.sh`.

## Out of scope
Models, APIs, pages, auth, migrations beyond Django defaults, PWA setup, deployment, branch
protection, hooking `scripts/cloud-setup.sh` into the routine environment (Kamran does that).

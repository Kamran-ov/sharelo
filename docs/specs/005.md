# Plan 005 — Analytics core: spending per person and per category

Ticket: `tickets/005-analytics-core.md` · risk: normal

## Current state
- `backend/ledger/services/` has `balances.py`, `expenses.py`, `rates.py`, `splits.py`; there is no `analytics.py`. Not already done.
- "Spending" = the OWED share, i.e. `ExpenseSplit.owed_cents`. A `personal` expense already writes a split of 100% to the payer
  (`splits.py`), so it needs no special case here.
- `Expense.objects` hides soft-deleted rows; `ExpenseSplit` has no `deleted_at`, so it is filtered through the expense relation
  (same approach as `balances.py`). Settlements are a separate table and are simply never queried.
- `Category.parent` is nullable, depth max 2 (`models.py`).

## Proposal
**`ledger/services/analytics.py`** — read-only; one aggregate query per function; integer cents only.
Shared private helper: base queryset of `ExpenseSplit` where `expense__group=group`, `expense__deleted_at IS NULL`,
`expense__date BETWEEN date_from AND date_to` (inclusive), and `member_id=member.id` when `member` is given.
Signature for all: `(group, date_from, date_to, member=None)`; a `member` from another group raises `LedgerError("member_not_in_group")`.
- `spending_by_member()` → `{member_id: cents}`; `Sum(owed_cents)` grouped by member. Every group member appears (0 if none); with
  `member` given, only that member.
- `spending_by_category(level=1|2)` → `{category_id: cents}`. Level 2 groups by the expense's own category. Level 1 groups by
  `Coalesce(category__parent_id, category_id)` so children roll into the parent in the same query. Other `level` → `LedgerError("invalid_level")`.
  Categories with no spending are omitted.
- `spending_by_month()` → `{"YYYY-MM": cents}` via `TruncMonth("expense__date")` (a `date`, no timezone shift). Months with none are omitted.
- `spending_by_member_and_category(level=1|2)` → `{member_id: {category_id: cents}}`; same rollup rule as above.
`spending_by_member_and_category(member=m)` returns `{m.id: {...}}`, outer key kept, so the shape is the same with or without `member`.
`date_from > date_to` returns empty dicts (assumed, no refusal, no test).
Guest members are included like any member here; excluding guests from Home is the job of the later linking ticket.

## Tests
`backend/tests/test_ledger_analytics.py` (DB), named for properties.
- `test_equal_expense_counts_by_share_not_by_payer` — **KEY**: €50 equal paid by A, split A/B → `{A: 2500, B: 2500}`. Red-proof mutation:
  aggregate the payers' `paid_cents` by payer instead of the splits' `owed_cents` by member → observed `{A: 5000, B: 0}` against expected
  `{A: 2500, B: 2500}`. The REPORT shows the failure on the dict-equality line, not on an error.
- `test_personal_expense_counts_fully_for_owner` — twin: personal €30 by A → `{A: 3000, B: 0}`. Own mutation: exclude
  `split_type == 'personal'` expenses from the base queryset (the balances-style bug) → observed `{A: 0, B: 0}`. It cannot see paid-vs-owed
  (payer and ower coincide), so it is not the key.
- Uncategorised spending: not a case — `Expense.category` is a non-null FK (`models.py`, `on_delete=PROTECT`), so every
  split has a category and the category totals always sum to the member totals. Asserted by `test_category_totals_sum_to_member_totals`
  (sum over `spending_by_category` at both levels equals sum over `spending_by_member` for the same range).
- `test_level1_totals_equal_sum_of_children` and `test_level2_keeps_children_separate` (a root-category expense stays under itself at level 1).
- `test_date_range_is_inclusive_on_both_ends` — expenses on from, to, day before, day after; only the first two count.
- `test_deleted_expense_excluded` (twin: same expense counted before deletion) and `test_settlement_never_counts_as_spending`.
- `test_other_group_excluded`.
- `test_member_filter_restricts_all_functions`; `test_member_of_other_group_refused` (twin: own member passes); `test_invalid_level_refused` (twin: 1 and 2 pass).
- `test_spending_by_month_buckets_by_expense_date` — an expense on the last and first day of adjacent months.
- `test_member_and_category_nested_sums_match_member_totals`.
- `test_<each function>_runs_in_exactly_one_query` — `django_assert_num_queries(1)` for each of the four functions, with 1 expense and again
  with many. `spending_by_member` lists zero-spend members in that one query by aggregating from `Member` with a filtered
  `Sum("<splits>__owed_cents", filter=...)` (LEFT JOIN), not from `ExpenseSplit`. The member-of-other-group check uses `member.group_id`, no query.
- `test_analytics_module_has_no_float_or_decimal` — source scan like the balances one.

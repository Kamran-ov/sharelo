# Plan 015 — Installable PWA, single-origin serving, laptop "production" compose

Ticket: `tickets/015-pwa-and-single-origin.md` · risk: normal

## Current state
Not done.
- `frontend/` has no manifest, icons, service worker or offline page (`frontend/index.html`, no `public/`, `vite.config.ts` has only react + tailwind plugins and an `/api` proxy).
- Django serves only `/api/*` and `/admin/` (`backend/sharelo/urls.py`); `STATIC_URL` is set but there is no `STATIC_ROOT`, no whitenoise (`backend/requirements.txt`), no catch-all view.
- Only `docker-compose.yml` (dev: runserver, `DEBUG=1`, bind mounts). `backend/Dockerfile` installs dev requirements and runs runserver. No gunicorn, no cron, no `compose.prod.yml`, no multi-stage image.
- `.env.example` lacks `ALLOWED_HOSTS`; `SECRET_KEY` has no real-secret guidance. `settings.py` already: `required_env("SECRET_KEY")`, `SESSION/CSRF_COOKIE_SECURE = not DEBUG`, `CSRF_TRUSTED_ORIGINS` and `ALLOWED_HOSTS` from env, an `E2E` block that neutralises security settings. No `SECURE_*` headers set (no `SECURE_SSL_REDIRECT`, HSTS, proxy header).
- E2E runs `vite preview` on 4173 proxying `/api` to the e2e backend on 8001 (`frontend/playwright.config.ts`).

## Proposal
**Frontend PWA.** Add `vite-plugin-pwa` (devDependency, pinned by the lockfile).
- Manifest (generated by the plugin): name `Sharelo`, short_name `Sharelo`, `start_url: "/"`, `display: standalone`, theme/background colour from the existing slate palette, icons 192, 512 and a 512 maskable. Icons are PNGs committed under `frontend/public/icons/`, produced once by `frontend/scripts/make-icons.mjs` (Playwright's Chromium rasterises the SVGs; PIL is not available) from a plain SVG (`frontend/public/icons/icon.svg`: solid colour + letter "S", no brand artwork); the script is run by hand, output committed, nothing generated at build time.
- Service worker (`generateSW`), one mechanism: **navigations are network-only and `offline.html` is the failure fallback; the app shell is never served as a navigation response from cache.** Config: `workbox.navigateFallback: null` (explicit: the plugin's `generateSW` default is `index.html`, which would register a NavigationRoute serving the cached shell for every navigation, `/admin/` included); `workbox.globIgnores: ["**/index.html"]` and `workbox.directoryIndex: null` so the precache route can never map `/` to the shell (the plugin's default `globPatterns` include html); `runtimeCaching: [{urlPattern: ({request}) => request.mode === "navigate", handler: "NetworkOnly", options: {precacheFallback: {fallbackURL: "/offline.html"}}}]`; `offline.html` is precached from the default `globPatterns` as its only source, with no `additionalManifestEntries` (a static file in `public/`, inline CSS, `<title>Offline — Sharelo</title>`, text "Sharelo needs a connection"); hashed JS/CSS/icon assets are precached as usual so the offline page and a later reload are instant. `/api/` and `/admin/` are not matched by any runtime route: they go straight to the network and **nothing under `/api/` is ever put in Cache Storage** (no NetworkFirst), so no authenticated response outlives logout and offline never shows stale balances. Mutations are never queued (no offline writes). `registerType: "autoUpdate"`.
- `src/components/InstallHint.tsx`: banner shown once when `display-mode: standalone` is false and (Android `beforeinstallprompt` captured → "Install" button; iOS Safari user agent → text "Tap Share, then Add to Home Screen"). Dismissal stored in `localStorage` (try/catch; page renders without it). Component logic takes `userAgent` and the captured event as inputs so tests can drive both branches. Rendered in `App.tsx` above routes, not on `/login`'s critical path.
- `index.html`: `<link rel="manifest">` comes from the plugin; add `theme-color` meta and `apple-touch-icon`.

**Single origin (Django).**
- `whitenoise` added to `requirements.txt`; `WhiteNoiseMiddleware` right after `SecurityMiddleware`. `STATIC_ROOT = BASE_DIR / "staticfiles"`. The built frontend is served at the site root: `WHITENOISE_ROOT = FRONTEND_DIST` (whitenoise indexes the dir at middleware construction; tests that need a different dir build a fresh `WhiteNoiseMiddleware` via `override_settings` + a new `Client` handler (`ClientHandler.load_middleware()`), the same helper used by every static-file test) (env `FRONTEND_DIST`, default `BASE_DIR / "frontend_dist"`, empty/missing dir is allowed so dev and tests boot). `STORAGES` staticfiles backend stays default (admin assets only); no hashed-manifest storage, so collectstatic works without a prior frontend build.
- `sharelo/spa.py: SpaIndexView` (plain `django.views.View`, no business logic): reads `FRONTEND_DIST/index.html` **on every request** (small file, no process cache, so tests with different temp dirs cannot see each other), returns it with `Cache-Control: no-cache`; 404 if the file is absent. `urls.py` appends `re_path(r"^(?!api(/|$)|admin(/|$)|static/).*$", SpaIndexView.as_view())` (bare `/api` and `/admin` stay out of the shell too; a test case covers `/api`). The regex sees paths without the leading slash, and the catch-all is appended last. Real files (sw.js, manifest, icons, assets) are answered by whitenoise before the URLconf.
- The exclusion is the KEY property: unknown `/api/...` paths must stay JSON/404, never `index.html`.
- `Makefile`: `build-frontend` (`cd frontend && npm ci && npm run build`, then copies `frontend/dist` → `backend/frontend_dist`; `backend/frontend_dist/` gitignored) and `collectstatic` target running after it. `make e2e` gains a second Playwright project (see Tests) rather than changing the existing one.

**Production compose** (`compose.prod.yml`, laptop).
- Multi-stage `Dockerfile` at the repo root: stage `web` (node:22-slim, `npm ci`, `npm run build`), stage `app` (python:3.12-slim, `pip install -r backend/requirements.txt` + `gunicorn` (added to `requirements.txt`), copy backend, `COPY --from=web /app/dist /app/frontend_dist`, `collectstatic --noinput`, `CMD gunicorn sharelo.wsgi -b 0.0.0.0:8000`). Existing `backend/Dockerfile` and dev compose untouched.
- Services: `db` (postgres:17 with a named volume, healthcheck), `backend` (build target `app`, `env_file: .env`, `DEBUG=0`, runs `migrate` then gunicorn via an entrypoint command `sh -c "python manage.py migrate --noinput && gunicorn …"`), `cron` (same image; installs supercronic at build as a second stage target `cron`, the Dockerfile commits literal `ARG SUPERCRONIC_VERSION` and `ARG SUPERCRONIC_SHA256` copied from the release page and verifies with `echo "$SUPERCRONIC_SHA256  supercronic" | sha256sum -c -` (build fails on mismatch); crontab file `deploy/crontab` with the single line `0 6 * * * python manage.py run_daily`). The cron container is the only added long-running process besides gunicorn, defined only in compose.
- Settings, final rule. `HTTPS = env HTTPS == "1"`. `SESSION_COOKIE_SECURE = CSRF_COOKIE_SECURE = HTTPS` (replaces `not DEBUG` at settings.py:106-107; `DEBUG` is no longer consulted for cookies). When `HTTPS`: `SECURE_PROXY_SSL_HEADER=("HTTP_X_FORWARDED_PROTO","https")`, `SECURE_SSL_REDIRECT=True`, `SECURE_HSTS_SECONDS=31536000`, `SECURE_HSTS_INCLUDE_SUBDOMAINS=True` (clears W005), `SECURE_HSTS_PRELOAD=True` (clears W021). Always: `SECURE_CONTENT_TYPE_NOSNIFF=True`, `SECURE_REFERRER_POLICY="same-origin"`, `X_FRAME_OPTIONS="DENY"`. No `SILENCED_SYSTEM_CHECKS`. Preload/subdomain flags only take effect over HTTPS and are harmless on a tunnel hostname; a registrable-domain choice is the release step.
- Two run modes, one `.env` switch: **local** (`HTTPS=0`, `ALLOWED_HOSTS=localhost,127.0.0.1`, open `http://localhost:8000`, no redirect, cookies not secure) and **tunnel** (`HTTPS=1`, `ALLOWED_HOSTS=<host>.trycloudflare.com`, `CSRF_TRUSTED_ORIGINS=https://<host>.trycloudflare.com`, open the https URL; `localhost:8000` then redirects to https and is no longer used). Switch: edit `.env`, then `docker compose -f compose.prod.yml up -d` (recreates `backend` with the new env). Documented in the README as that table.
- README section "Run it for real on your laptop": exactly five commands — `cp .env.example .env`; edit `.env` (SECRET_KEY, `python3 -c "import secrets;print(secrets.token_urlsafe(50))"`); `docker compose -f compose.prod.yml up -d --build`; `docker compose -f compose.prod.yml logs backend` (check migrate ran); open `http://localhost:8000` — then the tunnel line `cloudflared tunnel --url http://localhost:8000` and the two-mode table above. `.env.example` already holds `GOOGLE_CLIENT_ID` (empty disables Google sign-in); it gains `ALLOWED_HOSTS`, `HTTPS`, `CSRF_TRUSTED_ORIGINS` example, `SECRET_KEY` note.

**Config shape** (`webServer` is top-level in Playwright, not per project): one ordered array, started in order — (1) Django 8001 `e2e_prepare && runserver 8001` (existing, the only `e2e_prepare`), (2) `vite preview` 4173 (existing), (3) Django 8002 `runserver 8002 --noreload` with `FRONTEND_DIST=../frontend/dist`, **no `e2e_prepare`** (the database is already prepared by (1)). Both Djangos use the one `sharelo_e2e` database; `workers: 1` and `fullyParallel: false` (already set) cover both projects, so `e2e_reset` calls from any spec are serial. `projects`: `chromium-preview` (existing specs, `baseURL` 4173, `testIgnore: pwa.spec.ts`) and `served` (`testMatch: pwa.spec.ts`, `baseURL` http://localhost:8002). Both run in the same `make e2e` invocation, locally and in CI; a failure is attributed by project name in the list reporter. `frontend/dist` is built by `make e2e`'s existing `npm run build` before Playwright starts and is shared by preview and 8002 (running `npx playwright test` without `make e2e` is already unsupported, `docs/e2e.md`); a stale or missing `dist` cannot occur through `make e2e`. The `served` backend's `ALLOWED_HOSTS` stays `localhost,127.0.0.1` (E2E block).
Not covered: a real phone install (Kamran does that), `beforeinstallprompt` on a real Chrome, HTTPS/HSTS behind a real tunnel, supercronic actually firing at 06:00, a real offline reload on a phone, `docker compose build` and `config` (no Docker daemon in the cloud; only `config` validity is checked if `docker` exists, else the YAML test above).

**REPORT plan change (named up front):** the ticket's Scope says "precached app shell and network-first for `/api/`"; the plan deliberately precaches hashed assets and `offline.html` only, no `index.html`, and does not cache `/api/` at all (accepted at review rounds 1–2). Static files answered by whitenoise carry no `X-Frame-Options`, acceptable because only HTML documents (the SPA shell, served via Django's middleware stack) need frame protection.

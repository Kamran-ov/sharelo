# Plan 015 — Installable PWA, single-origin serving, laptop "production" compose

Ticket: `tickets/015-pwa-and-single-origin.md` · risk: normal

## Current state
Not done.
- `frontend/` has no manifest, icons, service worker or offline page (`frontend/index.html`, no `public/`, `vite.config.ts` has only react + tailwind plugins and an `/api` proxy).
- Django serves only `/api/*` and `/admin/` (`backend/sharelo/urls.py`); `STATIC_URL` is set but there is no `STATIC_ROOT`, no whitenoise (`backend/requirements.txt`), no catch-all view.
- Only `docker-compose.yml` (dev: runserver, `DEBUG=1`, bind mounts). `backend/Dockerfile` installs dev requirements and runs runserver. No gunicorn, no cron, no `compose.prod.yml`, no multi-stage image.
- `.env.example` lacks `ALLOWED_HOSTS`; `SECRET_KEY` has no real-secret guidance. `settings.py` already: `required_env("SECRET_KEY")`, `SESSION/CSRF_COOKIE_SECURE = not DEBUG`, `CSRF_TRUSTED_ORIGINS` and `ALLOWED_HOSTS` from env, an `E2E` block that neutralises security settings. No `SECURE_*` headers set (no `SECURE_SSL_REDIRECT`, HSTS, proxy header).
- E2E runs `vite preview` on 4173 proxying `/api` to the e2e backend on 8001 (`frontend/playwright.config.ts`).

## Proposal
**Frontend PWA.** Add `vite-plugin-pwa` (devDependency, pinned by the lockfile).
- Manifest (generated by the plugin): name `Sharelo`, short_name `Sharelo`, `start_url: "/"`, `display: standalone`, theme/background colour from the existing slate palette, icons 192, 512 and a 512 maskable. Icons are PNGs committed under `frontend/public/icons/`, produced once by `scripts/make-icons.py` from a plain SVG (`frontend/public/icons/icon.svg`: solid colour + letter "S", no brand artwork); the script is run by hand, output committed, nothing generated at build time.
- Service worker (`generateSW`): precache the built app shell; navigation fallback to `index.html` with `navigateFallbackDenylist: [/^\/api\//, /^\/admin\//]`; runtime route `/api/` → `NetworkFirst` with no cache for non-GET (mutations are never queued: no offline writes); an `offline.html` precached and served when a navigation fails (`setCatchHandler`/`navigateFallback` on network error) saying "Sharelo needs a connection". `registerType: "autoUpdate"`.
- `src/components/InstallHint.tsx`: banner shown once when `display-mode: standalone` is false and (Android `beforeinstallprompt` captured → "Install" button; iOS Safari user agent → text "Tap Share, then Add to Home Screen"). Dismissal stored in `localStorage` (try/catch; page renders without it). Rendered in `App.tsx` above routes, not on `/login`'s critical path.
- `index.html`: `<link rel="manifest">` comes from the plugin; add `theme-color` meta and `apple-touch-icon`.

**Single origin (Django).**
- `whitenoise` added to `requirements.txt`; `WhiteNoiseMiddleware` right after `SecurityMiddleware`. `STATIC_ROOT = BASE_DIR / "staticfiles"`. The built frontend is served at the site root: `WHITENOISE_ROOT = FRONTEND_DIST` (env `FRONTEND_DIST`, default `BASE_DIR / "frontend_dist"`, empty/missing dir is allowed so dev and tests boot). `STORAGES` staticfiles backend stays default (admin assets only); no hashed-manifest storage, so collectstatic works without a prior frontend build.
- `sharelo/spa.py: SpaIndexView` (plain `django.views.View`, no business logic): reads `FRONTEND_DIST/index.html` once per process, returns it with `Cache-Control: no-cache`; 404 if the file is absent. `urls.py` appends `re_path(r"^(?!api/|admin/|static/).*$", SpaIndexView.as_view())` **last**. Real files (sw.js, manifest, icons, assets) are answered by whitenoise before the URLconf.
- The exclusion is the KEY property: unknown `/api/...` paths must stay JSON/404, never `index.html`.
- `Makefile`: `build-frontend` (`cd frontend && npm ci && npm run build`, then copies `frontend/dist` → `backend/frontend_dist`; `backend/frontend_dist/` gitignored) and `collectstatic` target running after it. `make e2e` gains a second Playwright project (see Tests) rather than changing the existing one.

**Production compose** (`compose.prod.yml`, laptop).
- Multi-stage `Dockerfile` at the repo root: stage `web` (node:22-slim, `npm ci`, `npm run build`), stage `app` (python:3.12-slim, `pip install -r backend/requirements.txt` + `gunicorn` (added to `requirements.txt`), copy backend, `COPY --from=web /app/dist /app/frontend_dist`, `collectstatic --noinput`, `CMD gunicorn sharelo.wsgi -b 0.0.0.0:8000`). Existing `backend/Dockerfile` and dev compose untouched.
- Services: `db` (postgres:17 with a named volume, healthcheck), `backend` (build target `app`, `env_file: .env`, `DEBUG=0`, runs `migrate` then gunicorn via an entrypoint command `sh -c "python manage.py migrate --noinput && gunicorn …"`), `cron` (same image; installs supercronic at build as a second stage target `cron`, pinned version + sha256 of the release binary; crontab file `deploy/crontab` with the single line `0 6 * * * python manage.py run_daily`). The cron container is the only added long-running process besides gunicorn, defined only in compose.
- Settings for HTTPS: `HTTPS=1` env turns on `SECURE_PROXY_SSL_HEADER=("HTTP_X_FORWARDED_PROTO","https")`, `SECURE_SSL_REDIRECT=True`, `SECURE_HSTS_SECONDS=31536000`, and keeps secure cookies; with `HTTPS` unset and `DEBUG=0`, cookies are not marked secure (plain http on localhost must be able to sign in) — **this changes the current `SESSION_COOKIE_SECURE = not DEBUG`**: it becomes `HTTPS or not DEBUG-and-not-local`? To avoid ambiguity the rule is simply `SESSION/CSRF_COOKIE_SECURE = HTTPS`, with `DEBUG` no longer consulted. Always on: `SECURE_CONTENT_TYPE_NOSNIFF` (Django default), `SECURE_REFERRER_POLICY="same-origin"`, `X_FRAME_OPTIONS="DENY"`.
- `.env.example` gains `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` (example `https://xxxx.trycloudflare.com`), `HTTPS`, `FRONTEND_DIST` comment, with `SECRET_KEY` documented as "generate your own". README section "Run it for real on your laptop": 5 commands (cp env, edit, `docker compose -f compose.prod.yml up -d --build`, createsuperuser/none needed, open http://localhost:8000) + the `cloudflared tunnel --url http://localhost:8000` line and the note to put the printed host in `ALLOWED_HOSTS`/`CSRF_TRUSTED_ORIGINS` and `HTTPS=1`.

## Tests
**Backend (pytest, Postgres)** — new `backend/tests/test_spa_serving.py`, `test_prod_settings.py`.
- **KEY** `test_unknown_api_path_is_not_served_index_html`: with a temp `FRONTEND_DIST` holding an `index.html`, `GET /api/me` still returns the JSON (401/200 per auth) and `GET /api/does-not-exist/` returns 404 whose content type is not `text/html`. Red proof: remove the `api/` exclusion from the regex → this test fails (HTML body). Paired success cases: `test_deep_link_returns_index_html` (`/g/1/expenses` → 200, body is the file), `test_real_static_file_is_served_not_index` (`/manifest.webmanifest` returns the manifest bytes).
- `test_spa_view_404s_without_a_build` (no dist → 404, not a 500) paired with the success case above.
- `test_check_deploy_has_no_warnings_with_prod_env`: runs `call_command("check", deploy=True, fail_level="WARNING")` in a subprocess with env `DEBUG=0 HTTPS=1 SECRET_KEY=<50 random chars, not the django-insecure prefix> ALLOWED_HOSTS=example.com DATABASE_URL=… DJANGO_SETTINGS_MODULE=sharelo.settings`; asserts exit 0 and empty stderr. Paired refusal: same call with `HTTPS` unset must report W008/W012/W016 (proves the check is not vacuous).
- `test_cookie_secure_follows_https_flag` (HTTPS=1 → both secure; unset → neither), via subprocess settings import.
- `test_crontab_runs_run_daily_once_at_0600`: parses `deploy/crontab`, exactly one non-comment line, `0 6 * * *`, command ends `manage.py run_daily`.
- `test_compose_prod_declares_expected_services` (YAML load: services `db`, `backend`, `cron`; backend `DEBUG` not `1`; cron command not duplicated in any Makefile/script — grep the Makefile and `scripts/` for `supercronic` → none).

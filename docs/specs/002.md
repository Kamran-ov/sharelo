# Plan 002 — Split presets and rounding

Ticket: `tickets/002-split-presets.md` · risk: risky (money, rounding)

## Current state
- `backend/ledger/services/` has only `expenses.py` (`create_expense`, `update_expense`, `delete_expense`, `_validate`);
  there is no `splits.py`. `create_expense` takes explicit `payers` / `splits` dicts and already enforces both sum to total
  and every member belongs to the group. `SplitType` (exact enum strings) lives in `ledger/models.py`.
- No `CategoryDefault` model, no `default_split_for`, no `create_expense_from_preset`. The work is not already done.
- Tests live in `backend/tests/test_ledger_*.py`; migrations are `ledger/migrations/0001`, `0002_seed_categories` (never edited).

## Proposal
**`ledger/services/splits.py`** — pure functions, no imports from `django.db`, all return `dict[int, int]` (member_id → cents).
Module docstring states the rounding rule: floor every share, then give leftover cents one each to members in ascending
`member_id` order. One private helper `_distribute(total, weights: dict[int, int])` does this for equal, percentage and shares
(`floor = total * w // sum(w)`, leftover = `total - sum(floor)`, which is always `< len(weights)`); no other code rounds.
- `split_equal(total, member_ids)` → weights all 1. Duplicate ids raise.
- `split_personal(total, payer_id)` → `{payer_id: total}`. `split_full_for_other(total, other_id)` → `{other_id: total}`.
- `split_percentage(total, percents)` — values are **integer hundredths of a percent** (basis points; 5000 = 50.00%), must sum to
  exactly 10000. Weights = the basis points, so `_distribute` applies. Integer-only: no float or Decimal anywhere
  (FACTS). The ticket's "±0.005" tolerance only exists for decimal inputs and is moot with integers.
- `split_exact(total, cents)` — must sum to total, no negatives. Returned as a copy.
- `split_shares(total, shares)` — weights = shares, each must be a positive int.
- Validation common to all: `total_cents > 0` (`amount_not_positive`), non-empty members (`empty_members`), ids and values are `int`
  (bool rejected). New error codes: `empty_members`, `duplicate_member`, `invalid_share`, `percent_sum_mismatch`, `exact_sum_mismatch`,
  `invalid_params`, `unknown_preset`. Negative or zero shares/shares-weights → `invalid_share`; negative percent/exact → `negative_share`.
  A 0-bp percentage or 0-cent exact entry is allowed (legitimate: member left out), zero *shares* are refused per ticket.
- `split_for_preset(preset, total, member_ids, payer_id, params)` — dispatcher over `SplitType.values`. Params shapes:
  `equal` `{}`; `personal` `{}`; `full_for_other` `{"other_id": int}` (omitted + exactly two members → the member who is not the payer);
  `percentage` `{"basis_points": {id: int}}`; `exact` `{"cents": {id: int}}`; `shares` `{"shares": {id: int}}`.
  Param keys are normalised `str → int` first, because `CategoryDefault.split_params` is JSON and JSON object keys are strings.
  Unknown preset → `unknown_preset`; missing key → `invalid_params`. Every returned result is checked `sum == total` as a last guard.

**`CategoryDefault`** (`ledger/models.py`): `group` FK, `category` FK, `split_type` (choices `SplitType`, default `equal`),
`split_params` JSONField (default dict); `UniqueConstraint(group, category)` named `uniq_category_default`. New migration
`0003_categorydefault.py`. **Service** `default_split_for(group, category) -> tuple[str, dict]` in `ledger/services/splits.py`
(the only DB-touching function there, kept in a separate section; the pure functions never call it): returns the row's values
or `("equal", {})`. Only the exact category is looked up (no parent fallback; see Open questions).

**`create_expense_from_preset(group, *, preset, payer_id, member_ids=None, params=None, description, amount_cents, currency, date,
category, **rest)`** in `services/expenses.py`: `member_ids` defaults to all of the group's members (sorted); payers =
`{payer_id: amount_cents}`; splits = `split_for_preset(...)`; `split_type = preset`; then `create_expense`. No new transaction needed
(`create_expense` owns it; the split computation writes nothing). All existing validation (members in group, sums) still runs there,
so a `payer_id` from another group fails as `member_not_in_group`.

## Tests
`backend/tests/test_ledger_splits.py` (pure, no DB mark), `test_ledger_split_presets.py` (DB). Named for properties; each refusal has a passing twin.
- `test_every_split_sums_to_total` — **KEY**: for totals 1..1000 and member counts 2..5, for equal, percentage (33.33/33.33/33.34 style
  and 50/50 bps), shares (2:1:1…), `sum(result.values()) == total` and every value ≥ 0. Fails if the leftover loop is removed or
  mis-sized (sum then < total). Fixed loops, no hypothesis.
- `test_leftover_cents_go_to_lowest_member_ids` — 1000/3 → `{1: 334, 2: 333, 3: 333}`; ids passed unsorted `[9, 3, 5]` → 334 to 3 (not to 9);
  1001/3 → 334/334/333 (two leftovers go to two lowest ids). Passing twin: 999/3 → 333 each, no leftover.
- `test_percentage_must_sum_to_100` — 9999 and 10001 bps raise `percent_sum_mismatch`; 10000 passes; negative bp raises.
- `test_exact_must_sum_to_total` — off by one either way raises `exact_sum_mismatch`; exact passes.
- `test_shares_must_be_positive` — 0 and −1 raise `invalid_share`; 2:1 on 900 → 600/300 passes; 2:1 on 1000 → 667/333 (leftover to lowest id).
- `test_empty_members_refused` (`[]`, `{}` raise `empty_members`; one member is fine), `test_duplicate_member_ids_refused`,
  `test_total_must_be_positive` (0, −1 raise; 1 passes).
- `test_personal_owes_everything_to_payer` — `split_personal(1000, 4) == {4: 1000}`; `split_full_for_other` likewise `{other: total}`;
  dispatcher `full_for_other` with 2 members and no `other_id` picks the non-payer, with 3 members and no `other_id` raises `invalid_params`.
- `test_json_string_keys_accepted` — params shaped as stored in JSON (`{"basis_points": {"1": 7000, "2": 3000}}`) give the same result as int keys.
- `test_unknown_preset_refused` (`"bogus"` raises; each of the six enum strings dispatches).
- `test_personal_preset_expense_has_same_payer_and_sole_split` (DB) — `create_expense_from_preset(..., "personal")` in a 3-member group:
  1 payer row, 1 split row, same member, `split_type == "personal"`, amounts == total. Twin: `"equal"` yields 3 split rows summing to total.
- `test_preset_expense_rejects_payer_from_other_group` (refusal) paired with the success above.
- `test_default_split_for_returns_group_default_else_equal` — no row → `("equal", {})`; row set → its values; another group's row for
  the same category is ignored; `uniq_category_default` rejects a second row for (group, category) with `IntegrityError`.

## Edge cases (risky)
- Max leftover: with n weights, floor leaves `0 ≤ leftover < n`; asserted implicitly by the sum KEY test and explicitly by an assert in `_distribute`.
- Large weights: Python ints, so `total * w` cannot overflow; totals are cents, so no float drift is possible.
- Total smaller than member count (e.g. 1 cent, 3 members) → `{1: 1, 2: 0, 3: 0}`: zero shares in *results* are allowed and the ExpenseSplit check is `owed_cents >= 0`.
- JSON keys are strings (covered above). `bool` is an `int` subclass, so `True` as a member id or share is refused explicitly.

## Production checks (expected numbers)
- 1000 equal over ids [1,2,3] → `{1: 334, 2: 333, 3: 333}` (sum 1000). 1001 → `{334, 334, 333}`. 1 over 3 → `{1: 1, 2: 0, 3: 0}`.
- 1000 at 3333/3333/3334 bps → floor 333/333/333, leftover 1 to lowest id → `{1: 334, 2: 333, 3: 333}`. At 5000/5000 → 500/500.
- 1000 shares 2:1 → floor 666/333, leftover 1 → `{1: 667, 2: 333}`.
- Dispatcher `personal`, payer 4, total 2599 → `{4: 2599}`.

## Open questions
- **Assumed:** percentage inputs are integer basis points, not the ticket's "percent with 2 decimals", to keep Decimal/float out of money
  code (CLAUDE.md FACTS). The API layer later converts "33.33" → 3333 in one place. Reversible.
- **Assumed:** `default_split_for` has no parent-category fallback; a child without its own row gets `equal`. Reversible.
- **Assumed:** `full_for_other` with 2 members infers the other; with more it requires `other_id`.
